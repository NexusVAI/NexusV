Cancri API 文档

OpenAI / Anthropic 双协议兼容的统一模型 API。一个 Key，OpenAI SDK、 Anthropic SDK、Codex CLI、Claude Code、OpenCode、OpenClaw 都能直接接入。

概述

Cancri API 在一个端点后面统一了 GPT、Claude、Gemini、DeepSeek、GLM、 Qwen 等主流模型，同一把 Key，三种协议——选你的客户端原生支持的 那一种就行：

路径 协议 适合的客户端
POST /v1/chat/completions OpenAI Chat Completions openai SDK、LangChain、LiteLLM、OpenCode 等
POST /v1/responses OpenAI Responses Codex CLI（默认协议）
POST /v1/messages Anthropic Messages Claude Code、@anthropic-ai/sdk、OpenClaw
GET /v1/models OpenAI / Anthropic 自适应 带 anthropic-version header 时返回 Anthropic 格式
Base URL： https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway
  • 认证：Authorization: Bearer cancri_sk_xxx 或 x-api-key: cancri_sk_xxx
  • 支持流式（SSE）和非流式两种模式
  • 所有模型在 模型广场 可见
  • 图像 / 视频生成只在网页版开放，不对外 API 暴露
稳定的模型 ID。 你看到的 model 字段（如 gpt-5.4、deepseek-v4-pro、claude-sonnet-4-6） 是 Cancri 维护的稳定品牌 ID。后端会自动负载均衡与故障切换， 调用方不需要感知具体路由，也不需要为故障切换调整 model 字段。

认证

所有 API 请求都必须在 Authorization 头里带 Bearer Token。Key 形如：

cancri_sk_48 个十六进制字符

前缀 cancri_sk_（10 字符）+ 36 字节随机熵的 base64url 编码（48 字符）= 总长度恒为 58 字符。 后半部分字符集为 A-Z a-z 0-9 - _（不含 + / = 填充符）。 做 Key 正则校验的客户端推荐用 /^cancri_sk_[A-Za-z0-9_-]{48}$/。

  1. 到 申请页 提交申请
  2. 审核通过后到 Keys 管理页 生成 Key
  3. 把 Key 安全存好（生成后只显示一次）
⚠️ 不要在浏览器代码或开源仓库里硬编码 Key。 Key 一旦泄露， 立刻到 Keys 管理页撤销并重新生成。

每个账号最多同时持有 5 个 活跃 Key，超过需先撤销旧的。

Chat Completions

POST /v1/chat/completions

调用任意聊天模型生成回答，支持流式与非流式。

请求参数

参数 类型 必填 说明
model string 是 模型 ID，例如 deepseek-v4-pro。完整列表见 模型广场
messages array 是 消息历史，元素 {role, content}
stream boolean 否 设 true 启用 SSE 流式输出，默认 false
temperature number 否 0-2，越高越随机，默认 1
max_tokens number 否 最大生成 tokens，受模型能力上限约束
top_p number 否 0-1 核采样阈值
tools array 否 函数调用工具集（部分模型支持）

非流式示例

curl https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway/v1/chat/completions \
  -H "Authorization: Bearer cancri_sk_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-v4-pro",
    "messages": [
      {"role": "system", "content": "你是简洁的助手"},
      {"role": "user", "content": "用一句话解释 RLS"}
    ]
  }'

console.log(r.choices[0].message.content);

流式（SSE）示例

curl https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway/v1/chat/completions \
  -H "Authorization: Bearer cancri_sk_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -N \
  -d '{
    "model": "deepseek-v4-pro",
    "messages": [{"role":"user","content":"hello"}],
    "stream": true
  }'
const stream = await client.chat.completions.create({
  model: "deepseek-v4-pro",
  messages: [{ role: "user", content: "hello" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content || "");
}
stream = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[{"role": "user", "content": "hello"}],
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)
SSE 格式： 每个事件以 data: 开头的 JSON 行， 最后以 data: [DONE] 结束。每个 chunk 的 choices[0].delta.content 是增量文本。

Messages（Anthropic 协议）

POST /v1/messages

Anthropic Messages API 兼容，给 Claude Code、官方 @anthropic-ai/sdk、 OpenClaw 等以 Anthropic 协议为母语的客户端用。请求体和响应体严格符合 Anthropic 规范，且 model 字段不限于 Claude 系列 —— claude-sonnet-4-6、gpt-5.4、deepseek-v4-pro 都可以直接传，网关内部会做协议翻译。

请求参数

参数 类型 必填 说明
model string 是 模型 ID（与 Chat Completions 共用同一份 模型广场）
messages array 是 Anthropic 风格的对话历史（支持 text / image / tool_use / tool_result content blocks）
system string / array 否 系统提示，单字符串或 text-block 数组都可以
max_tokens number 是 Anthropic 协议要求显式指定最大输出
stream boolean 否 true 走 Anthropic SSE 帧（message_start / content_block_delta / message_stop）
tools array 否 Anthropic 工具定义 {name, description, input_schema}，工具调用结果通过 tool_use / tool_result 往返

非流式示例

curl https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway/v1/messages \
  -H "x-api-key: cancri_sk_YOUR_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 256,
    "system": "你是简洁的助手",
    "messages": [{"role":"user","content":"用一句话解释 RLS"}]
  }'
// npm i @anthropic-ai/sdk
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: "cancri_sk_YOUR_KEY",
  baseURL: "https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway",
});

const r = await client.messages.create({
  model: "claude-sonnet-4-6",
  max_tokens: 256,
  system: "你是简洁的助手",
  messages: [{ role: "user", content: "用一句话解释 RLS" }],
});
console.log(r.content[0].text);

流式（SSE） 在请求里加 "stream": true 即可，输出严格符合 Anthropic 事件协议——message_start → content_block_start → content_block_delta×N → content_block_stop → message_delta → message_stop。Claude Code 默认走这条路径。
当前限制： cache_control（提示缓存）字段会被忽略； extended thinking blocks 当作普通文本透传；Responses-only 的 web_search/ file_search 等内置工具不支持，仅 function 类自定义工具可用。

Responses（OpenAI 新协议）

POST /v1/responses

OpenAI Responses API 兼容，主要给 Codex CLI 这类默认走新协议的客户端用。 字段名跟 Chat Completions 不太一样（input 而不是 messages， instructions 而不是 system 消息，max_output_tokens 而不是 max_tokens 等）——网关会自动转换到内部 Chat 协议再翻译回来。

请求参数

参数 类型 必填 说明
model string 是 模型 ID。Codex 推荐 gpt-5.3-codex / gpt-5.4
input string / array 是 输入：单字符串简写，或 {type, role, content} / function_call / function_call_output 项的数组
instructions string 否 系统提示，会自动提到 input 最前面
max_output_tokens number 否 最大生成 tokens（也兼容 max_tokens）
stream boolean 否 true 走 Responses SSE（response.created / response.output_text.delta / response.completed）
tools array 否 Responses 风格 {type:"function", name, description, parameters}。web_search/file_search 等内置工具暂不支持

非流式示例

curl https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway/v1/responses \
  -H "Authorization: Bearer cancri_sk_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.3-codex",
    "instructions": "你是简洁的助手",
    "input": [
      {"type":"message","role":"user","content":[{"type":"input_text","text":"用一句话解释 RLS"}]}
    ],
    "max_output_tokens": 256
  }'
// 用官方 openai 包，新协议走 client.responses
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: "cancri_sk_YOUR_KEY",

});

const r = await client.responses.create({

  instructions: "你是简洁的助手",

不想折腾新协议？ Codex CLI 也支持 wire_api = "chat"，可以让它走 Chat Completions，这样所有内部转换都跳过去，更简单。配置见 下面的 Codex CLI 一节。

Codex CLI 接入

OpenAI 官方编码 CLI。把它指向我们的网关后，它就能用我们这边的所有模型。 编辑 ~/.codex/config.toml： 

model = "gpt-5.3-codex"
model_provider = "cancri"

[model_providers.cancri]
name = "Cancri"
base_url = "https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway/v1"
wire_api = "responses"
env_key = "CANCRI_API_KEY"

然后注入 Key 启动：

export CANCRI_API_KEY="cancri_sk_YOUR_KEY"
codex
想走更稳定的 Chat Completions 协议？把 wire_api = "responses" 改成 wire_api = "chat" 即可。两条路径 Codex 都支持。

Claude Code 接入

Anthropic 官方编码 CLI。把它的两个环境变量指过来即可： 

export ANTHROPIC_BASE_URL="https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway"
export ANTHROPIC_AUTH_TOKEN="cancri_sk_YOUR_KEY"
claude

启动后 Claude Code 会自动调 /v1/models 拉模型列表（网关检测到 anthropic-version 头会自动返回 Anthropic 格式）。模型选择器里挑 claude-sonnet-4-6 / claude-opus-4-5 或者其它兼容模型都行。

OpenCode 接入

        "apiKey": "cancri_sk_YOUR_KEY"
      },
      "models": {
        "gpt-5.4": {},
        "gpt-5.3-codex": {},
        "claude-sonnet-4-6": {},
        "deepseek-v4-pro": {},
        "gemini-3.1-pro-preview": {}
      }
    }
  }
}

OpenClaw 接入

openclaw/openclaw 默认走 Anthropic 协议，所以直接复用 Claude Code 那套环境变量：

}

Cherry Studio 接入指南

Cherry Studio 是一款优雅、强大的跨平台桌面级 AI 客户端，支持多模型对比、RAG 本地知识库等丰富功能。

配置步骤：

  1. 打开 Cherry Studio，点击左下角的 设置 (Gear 图标)。
  2. 在左侧菜单选择 模型服务商。
  3. 点击下方的 添加自定义服务商，或在内置服务商列表中选择 OpenAI (Custom) 并启用。
  4. 在参数输入框中填入以下信息：
    • 服务商名称： Cancri
    • API Key (密钥)： 填入你的 cancri_sk_YOUR_KEY
    • API 地址 (Endpoint)： https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway/v1 (注意：末尾必须带上 /v1)
  5. 点击 管理模型 或 刷新模型 按钮，Cherry Studio 将自动访问 /v1/models 并获取全量支持的模型列表，无需手动一个个输入！
  6. 配置完成后，在对话窗口顶部选择对应的 Cancri 模型（如 gpt-5.4 或 claude-sonnet-4-6）即可开始聊天！

SillyTavern (酒馆) 接入指南

SillyTavern（俗称酒馆）是面向深度提示词工程、虚拟角色扮演以及小说创作爱好者的顶级高级前端客户端。

配置步骤：

  1. 启动 SillyTavern 并打开网页端。点击顶部导航栏 of API 连接 (插头图标)。
  2. 在 API 下拉菜单中选择 Chat Completion。
  3. 在 Chat Completion Source (服务商) 菜单中选择 Custom (OpenAI-compatible)。
  4. 在下方输入框中配置：
    • API Key： 填入你的 cancri_sk_YOUR_KEY
    • Custom Endpoint (逆向API地址/基址)： https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway/v1 (注意结尾必须带 /v1 且不能多出额外的斜杠)
  5. 点击右侧的 Connect (连接) 按钮。
  6. 当状态指示灯变为 绿色 (已连接) 时，在 Model 下拉列表中选择你想调用的具体模型 ID（例如 gpt-5.4, claude-opus-4-6, deepseek-v4-pro, gemini-3.1-pro ）。
  7. 建议在 SillyTavern 的上下文与 Prompt 格式中配置适配你所用模型的 Pre-sets，以获得最佳演绎效果。

CC Switch 接入指南

CC Switch 是一款在开发者间大火的、专注于统一管理 AI 编程 CLI 工具（如 Claude Code, Codex, OpenCode, OpenClaw 等）的系统级多合一客户端托盘。

配置步骤：

  1. 打开 CC Switch 桌面客户端面板。
  2. 切到 Settings (设置) -> Providers (服务商) 页面。
  3. 点击 Add Custom Provider (添加自定义服务商)。
  4. 填入配置信息：
    • Provider Name (名称)： Cancri
    • Base URL (地址)： https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway/v1
    • API Key： cancri_sk_YOUR_KEY
  5. 点击 Test Connection (连接测试)。CC Switch 会调用 /v1/models 自行拉取可用的模型。
  6. 在路由 takeover 功能中，你可以一键将 Claude Code 或 Codex 的路由劫持/转发给 Cancri，从此命令行里的 AI 编程工具直接免代理运行！

Chatbox 接入指南

Chatbox 是一款开源、极简且多端同步的 AI 跨平台客户端，支持 Mac, Windows, iOS 与 Android。

配置步骤：

  1. 启动 Chatbox，点击左下角的 设置 (Gear)。
  2. 在 模型提供方 下拉框中，选择 OpenAI 兼容 (OpenAI Compatible)。
  3. 配置对应字段：
    • API 密钥 (API Key)： 你的 cancri_sk_YOUR_KEY
    • API 域名 (API Host/Base URL)： https://diusqgphvybnzazgopor.supabase.co/functions/v1/api-gateway/v1
  4. 在 模型 (Model) 输入框中填入你想默认调用的模型 ID，或者点击刷新加载列表。
  5. 保存并返回主页，即可无缝发起流畅多端会话。

常见问题与解答 (Q&A)

Q: 报错 503 Service Unavailable 并带代码 "api_paused" 是怎么回事？

A: 这是站内的API维护闸门限制。当平台准备上线全新的 ¥9.9/月 付费订阅配额时，系统会暂停纯公网非网页端 API 的写入操作以防恶意攻击，而 /v1/models 路由保持开放发现。如果是平台管理员或内部进行测试，只需在 Supabase 控制面板将 Secret 环境变量 API_PAUSED_UNTIL_PAID 设为 false 即可秒级解除此 503 限制，重新开放全站 API 接口。

Q: Paid（付费）账户和 Free（免费）账户的 API 限制有何不同？

A: 网站上的公共文档默认展示的是免费档防刷限制，实际上后台针对付费/VIP用户的限流极其宽裕，具有极其显著的体验优势：
• 并发数： 免费用户单 Key 限 2 并发；付费用户和 VIP 用户无并发数限制 (maxConcurrent=0，允许任意多路多线程并行)。
• 频次限制： 免费用户 10 次/分、1000 次/天；付费用户放宽到 60 次/分、600 次/小时、50000 次/天，完美承载各种高频编程辅助 (如 Aider, Claude Code) 与高频测试场景。

Q: 报错 404 model_not_found 如何解决？

A: 请确保你在客户端内填写的模型 ID 拼写完全正确，且存在于 /v1/models 返回的列表中（例如 gpt-5.4, claude-opus-4-6 ）。一些第三方软件会私自转换模型名字，请在模型设置中手动输入完全一致的 Cancri Canonical ID。

Q: API 支持图片和视频生成吗？

A: 根据平台规范，图像生成 (/v1/images/generations) 和视频生成 (/v1/videos/generations) 由于接口防刷和异步长轮询特性，不对公网 API Key 开放，仅在 Cancri 官方网页版前端可流畅调用和合成。

配额机制（2026-05-17 Phase A）

Cancri 把模型分成 FREE 与 PAID 两档（见 模型广场 每张卡片右上的 badge）。FREE 档对所有用户始终免费；PAID 档对 FREE 用户 开放有限的免费试用，对 PAID 订阅用户按月度配额计费。订阅分三档： Pro（¥9.9 / 月 / 2000 万 token）、 Pro+（¥29 / 月 / 8000 万 token，解锁 Claude Opus 全系）、 Pro Max（¥99 / 月 / 3 亿 token，全模型 + 视频图像）。 另外有加油包（¥10 / ¥50 / ¥200，永不过期）可在月度配额耗尽后接续使用。

FREE 用户的 PAID 模型试用规则

  • 全站共享池： 每月 1 亿 token（按下文折算后的 effective_pool_tokens 计），所有 FREE 用户共享。每月 1 号 00:00（UTC+8）自动重置回 1 亿。 池内余额耗尽后，当月所有 FREE 用户调 PAID 模型都会被立刻拦截 （返回 429 free_pool_exhausted），直到下月初。
  • 每日个人限额： 每个 FREE 用户每天最多 15 次 PAID 模型成功调用 （UTC+8 自然日，每天 00:00 重置）。上限内由共享池继续扣量； 用满会返回 429 daily_paid_limit_reached。
  • 失败不计数： 上游错误（HTTP 5xx、上游 unavailable、key 失效、 quota 等返回 4xx/5xx 的失败请求）会自动 refund —— 不扣 15 次/日， 也不扣共享池。判定基于 HTTP 状态码，不读取上游错误文本。
  • GPT-5.5 / GPT-5.4 Mini 例外： gpt-5.5 / gpt-5.5-high / gpt-5.4-mini 是 Pro 以上专属， FREE 用户调用直接返回 403 model_pro_required， 不计入共享池与每日 15 次。
  • Claude Opus 系列例外： claude-opus-4-5 / claude-opus-4-6 / claude-opus-4-6-thinking 等 vip 级模型仅 Pro+ 以上可用，FREE 与 Pro 调用都返回 403 model_pro_plus_required。
    2026-05-17 Phase A 老用户豁免： 在 2026-05-17 之前订阅的 Pro 用户， get_quota_status 返回的 is_grandfathered=true， 在本订阅周期内可继续调用 Claude Opus 全系（权重 30× 仍生效），到期/续费后自动失效。

PAID 订阅用户的月度配额

  • plan_code 决定额度： Pro = 2000 万 token / 月；Pro+ = 8000 万 / 月； Pro Max = 3 亿 / 月。每次成功调用扣除 effective_pool_tokens × 模型权重（见下方权重表）。
  • 订阅周期自动重置： 付费订阅按激活后的每 30 天周期懒重置（消费或查询额度时由 cancri_consume_paid_quota_v2 / cancri_get_quota_status_v2 检测并归零）。周期内续费只延长有效期，不会立刻清零，避免通过反复续费刷配额。
  • 加油包接续： 本周期套餐配额耗尽后自动从加油包余额扣减；都为 0 时返回 429 monthly_quota_exhausted。
  • 失败不扣： 同 FREE 用户一样，上游 4xx/5xx 自动 refund 到原桶。

token 折算公式

每次成功调用入池的有效 token 数（effective_pool_tokens）按 上游返回的真实 usage 字段折算。缓存命中按 10% 计价（与 Anthropic / OpenAI prompt caching 主流商家一致）： 

effective_pool_tokens
  = (prompt_tokens - cached_tokens) × 1.0       // 普通输入（全价）
  + cached_tokens                  × 0.1       // 缓存命中（10% 折扣）
  + completion_tokens              × 1.0;      // 输出（全价）

# 最终扣减 = effective_pool_tokens × 模型权重

上游字段映射：OpenAI 协议读 usage.prompt_tokens / usage.completion_tokens / usage.prompt_tokens_details.cached_tokens； Anthropic 协议读 usage.input_tokens / usage.output_tokens / usage.cache_read_input_tokens（cache_creation_input_tokens 按全价计算，因为是首次写入缓存）。流式 SSE 取最后一帧的 usage 字段； 若上游未返回 usage（中转商不规范），按已透出的 delta 文本估算 output_tokens ≈ chars / 4 兜底入池。

每个成功响应都会带以下 6 个限流头，客户端可据此预估节奏：

撞限后的 429 响应额外带：

  • X-RateLimit-Scope：哪一道防线被撞（per_minute / per_hour / per_day）
并发与模型排队不记在响应头里。 超过并发上限或模型 lane 已满时， 会以 concurrent_limit_exceeded 或 model_queue_full （见下一节）拒接，请按错误码描述决定重试或换模型。

429 识别速查

拿到 429 时按 error.code 区分原因：

  • rate_limit_exceeded → 撞到账户总闸（见上表）， 结合 X-RateLimit-Scope 决定退避；同模型重试可行。
  • concurrent_limit_exceeded → 并发上限（free=2）已用尽， 等已有请求结束再发新请求。Paid 不会触发此码。
  • model_queue_full → 当前模型 free 通道满员，响应体里 queue_position 给出排位。建议：等 10~30 秒重试， 或换一个模型，或升级到 Paid跳过这道闸。
  • upstream_rate_limit → 该模型当前繁忙、暂时不可用。 同模型短时间内重试无效，建议立即换模型。

错误码

HTTP code 说明
400 — 请求体格式错误或缺必填字段（type: invalid_request_error）
401 invalid_api_key Key 不存在 / 已撤销 / 格式错误
404 model_not_found model 字段不在可用列表里。两种可能：不存在或 被健康度临时隐藏（见下节）。

模型健康度自动熔断

为了不让调用方在临时不可用的模型上浪费重试额度，后端在 10 分钟的滑动窗口内计每个模型的不可用信号（1 次任意 2xx 会重置计数）：

  • 累计 ≥ 3 次不可用返回 → 该模型被熔断 60 分钟，期间调用返回 503 model_temporarily_unavailable（带 Retry-After 头）
  • 60 分钟冷却后自动解锁，无需人工介入；下次调用成功则立即清除计数
  • 被熔断的模型 仍然出现在 /v1/models 列表里，只是调用会 被拒；列表本身不会隐藏
  • 极端信号（如 401/402 上游 Key 死亡）会写入 DB 以 24 小时为周期硬禁用， 需管理员到 admin_lines.html 手动重新启用

拿到 503 upstream_error 不要在同模型上原地重试。看 Retry-After 后退避，或直接换一个模型。

错误响应格式按调用端点协议返回，客户端只需按本来 SDK 的错误处理流程即可：

  • OpenAI 协议路由（/v1/chat/completions / /v1/responses） 走 OpenAI shape：{ "error": { "message", "type", "code" } }
  • Anthropic 协议路由（/v1/messages）走 Anthropic shape： { "type": "error", "error": { "type", "message", "code" } } —— Claude SDK / Claude Code / OpenClaw 期望此形态，原生 SDK 无需特殊处理
{
  "error": {
    "message": "...",
    "type": "invalid_api_key",
    "code": "invalid_api_key"
  }
}

三个端点我该用哪个？

  • 无脑用 /v1/chat/completions——支持的 SDK / 工具最多，调用最稳。

/v1/images/generations 和 /v1/videos/generations 已下线 API 入口，改为只在网页版可用。如果你之前在调用，会收到 403 endpoint_disabled。后续如果重开会在这里另行说明。

CLI 模型选择器里看不到我想要的模型？

CLI（特别是 Claude Code）启动时会拉一次 /v1/models，名字必须跟那 一份列表对得上。直接 curl /v1/models 看一下，或到 模型广场 查可用 ID；不要照搬 Anthropic / OpenAI 官方 的版本号（比如 claude-3-5-sonnet-20241022 这边没有）。

tool calling（function calling）支持吗？

三条路径都支持，自定义 function 工具会原样翻译往返。但 Responses 协议 的 web_search / file_search / computer_use 等内置工具暂未实现，传过来会被忽略。

怎么追踪用量？

到 Keys 管理页 可看到每个 Key 的最后使用时间、 最近 30 天调用次数、token 消耗与按模型的分布。

怎么升到 Paid 档？现有 Key 还能用吗？

到 套餐页扫码付款（Pro ¥9.9 / Pro+ ¥29 / Pro Max ¥99 / 30 天订阅周期， 或¥10 起的加油包）并提交订单，站主人工对账后会给一个一次性激活码，在 我的订单里兑换即可立即生效。 升档不影响现有 Key——同一把 Key 在 Free 和 Paid 下用法完全一致， 限流阈值会自动按你当前档位生效。Paid 到期后会自动降回 Free， cancri_sk_ 本身不会失效。

能在浏览器里直接调吗？

不要。Key 暴露在前端等于免费送给所有人。请始终从你的服务端转发。

支持的国家/IP 限制？

后端会做地域级速率限制和 IP 维度风控，但不主动屏蔽国家。 如发现可疑流量会临时封锁。

Key 丢了怎么办？

生成时只显示一次，无法找回。到 Keys 管理页 撤销旧 Key，重新生成。

计费怎么算？

后台实计费按 effective_pool_tokens × 模型权重 扣减（见上面「模型权重表」）： Free 档免费使用全站 1亿/月共享池 + 个人每日 15 次 PAID 试用； Pro ¥9.9 / 30 天订阅周期 个人周期配额 2000 万 token， Pro+ ¥29 / 30 天订阅周期 8000 万 token + Claude Opus， Pro Max ¥99 / 30 天订阅周期 3 亿 token + 视频图像优先，加油包 ¥10 起永不过期，见 套餐页。

有 SLA 吗？

没有。Cancri 是个人维护的非营利项目，订阅费用于覆盖运营成本。 服务尽力保证可用，但不承诺 SLA、不承诺特定模型永远在线、不承诺响应延迟。 生产关键路径请自行做故障转移。
