Cancri API 文档

Cancri API 提供 OpenAI Chat Completions、OpenAI Responses 与 Anthropic Messages 三条兼容路径。第三方工具能否接入，取决于它是否允许自定义 Base URL、API Key 和模型 ID。

概述

Cancri API 在一个端点后面统一了 GPT、Claude、Gemini、DeepSeek、GLM、 Qwen 等模型，同一把 Key，三种协议。优先选择客户端原生支持的 协议；IDE/Agent 的厂商托管模式不会自动继承这个自定义网关。

路径 协议 适合的客户端
POST /v1/chat/completions OpenAI Chat Completions openai SDK、LangChain、LiteLLM、OpenCode 等
POST /v1/responses OpenAI Responses Codex CLI（默认协议）
POST /v1/messages Anthropic Messages Claude Code、@anthropic-ai/sdk、OpenClaw
POST /v1/messages/count_tokens Anthropic Token Counting Claude Code 自动调用；免费、不计配额
GET /v1/models OpenAI / Anthropic 自适应 带 anthropic-version header 时返回 Anthropic 格式
Base URL： https://chat.nexusvai.xyz/functions/v1/api-gateway
统一入口：无论调哪个协议，请求都发到 chat.nexusvai.xyz/functions/v1/api-gateway。 网关负责鉴权、选路、流式转发与用量统计；你不需要关心底层线路切换。

稳定的模型 ID。 你看到的 model 字段（如 gpt-5.4、deepseek-v4-pro、claude-sonnet-4-6） 是 Cancri 维护的稳定品牌 ID。调用方不需要感知具体路由， 保持模型 ID 不变即可。

认证

推理请求需要带公开 API Key。网关接受两种等价认证头： Authorization: Bearer cancri_sk_xxx 或 x-api-key: cancri_sk_xxx。Key 形如：

cancri_sk_48 个 base64url 字符

前缀 cancri_sk_（10 字符）+ 36 字节随机熵的 base64url 编码（48 字符）= 总长度恒为 58 字符。 后半部分字符集为 A-Z a-z 0-9 - _（不含 + / = 填充符）。 做 Key 正则校验的客户端推荐用 /^cancri_sk_[A-Za-z0-9_-]{48}$/。

  1. 到 申请页 提交申请
  2. 审核通过后到 Keys 管理页 生成 Key
  3. 把 Key 安全存好（生成后只显示一次）
⚠️ 不要在浏览器代码或开源仓库里硬编码 Key。 Key 一旦泄露， 立刻到 Keys 管理页撤销并重新生成。
API Key 与网页登录是两套体系。 cancri_sk_ 只用于 /v1/* 公开 API；网页版聊天、设置页、订单等使用独立的用户会话。 不要把 cancri_sk_ 填到网页版客户端配置里。

你可以生成任意数量的 Key，但建议按需创建，过多 Key 会增加管理复杂度。

易混淆点

  • /v1/models 成功不代表写接口开放。 维护闸门开启时，模型列表仍可读，/v1/chat/completions、/v1/messages、/v1/responses 会返回 503 api_paused。
  • 不要尝试绕过网关。 公开客户端只调用 /functions/v1/api-gateway；其它未公开地址不对外服务。
  • 模型 ID 必须使用 Cancri Canonical ID。 model 字段的值必须来自 模型广场 或 /v1/models 返回值，不要直接照搬 OpenAI / Anthropic 官方版本号（如 gpt-4-turbo、claude-3-5-sonnet-20241022）。
  • OpenAI 兼容 SDK 的 Base URL 末尾要带 /v1，Anthropic SDK 不要带。 Anthropic SDK 和 Claude Code 会自行拼 /v1/messages、/v1/messages/count_tokens。
  • 兼容协议 ≠ 完整上游平台能力。 公开 API 支持核心对话、流式输出、token usage 与自定义 function tools；OpenAI hosted tools、Responses 状态、文件 / 向量库、网页搜索、computer use 不在支持范围内。

Chat Completions

POST /v1/chat/completions

调用任意聊天模型生成回答，支持流式与非流式。

请求参数

参数 类型 必填 说明
model string 是 模型 ID，例如 deepseek-v4-pro。完整列表见 模型广场
messages array 是 消息历史，元素 {role, content}
stream boolean 否 设 true 启用 SSE 流式输出，默认 false
temperature number 否 0-2，越高越随机，默认 1
max_tokens number 否 最大生成 tokens，受模型能力上限约束
top_p number 否 0-1 核采样阈值
tools array 否 函数调用工具集（部分模型支持）

流式（SSE）示例

curl https://chat.nexusvai.xyz/functions/v1/api-gateway/v1/chat/completions \
  -H "Authorization: Bearer cancri_sk_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -N \
  -d '{
    "model": "deepseek-v4-pro",
    "messages": [{"role":"user","content":"hello"}],
    "stream": true
  }'
const stream = await client.chat.completions.create({
  model: "deepseek-v4-pro",
  messages: [{ role: "user", content: "hello" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content || "");
}
stream = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[{"role": "user", "content": "hello"}],
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)
SSE 格式： 每个事件以 data: 开头的 JSON 行， 最后以 data: [DONE] 结束。每个 chunk 的 choices[0].delta.content 是增量文本。

Messages（Anthropic 协议）

POST /v1/messages

Anthropic Messages API 兼容路径，适用于 Claude Code、官方 @anthropic-ai/sdk、 OpenClaw 等客户端。支持 Messages 核心字段，但不是 Claude 官方 API 全功能复刻。 model 字段不限于 Claude 系列 —— claude-sonnet-4-6、gpt-5.4、deepseek-v4-pro 都可以直接传。

请求参数

参数 类型 必填 说明
model string 是 模型 ID（与 Chat Completions 共用同一份 模型广场）
messages array 是 Anthropic 风格的对话历史（支持 text / image / tool_use / tool_result content blocks）
system string / array 否 系统提示，单字符串或 text-block 数组都可以
max_tokens number 是 Anthropic 协议要求显式指定最大输出
stream boolean 否 true 走 Anthropic SSE 帧（message_start / content_block_delta / message_stop）
tools array 否 Anthropic 工具定义 {name, description, input_schema}，工具调用结果通过 tool_use / tool_result 往返

非流式示例

curl https://chat.nexusvai.xyz/functions/v1/api-gateway/v1/messages \

  -H "Content-Type: application/json" \

    "model": "claude-sonnet-4-6",
    "max_tokens": 256,
    "system": "你是简洁的助手",

Responses（OpenAI 新协议）

POST /v1/responses

OpenAI Responses API 兼容路径，适用于 Codex CLI 等默认走该协议的客户端。 字段名与 Chat Completions 不同（如 input 代替 messages， instructions 代替 system 消息，max_output_tokens 代替 max_tokens）。网关会在 Responses 与 Chat 协议之间自动转换。 这是面向客户端接入的适配层，不提供 OpenAI hosted tools、状态托管或文件检索能力。

请求参数

参数 类型 必填 说明
model string 是 模型 ID。Codex 推荐 gpt-5.3-codex / gpt-5.4
input string / array 是 输入：单字符串简写，或 {type, role, content} / function_call / function_call_output 项的数组
instructions string 否 系统提示，会自动提到 input 最前面
max_output_tokens number 否 最大生成 tokens（也兼容 max_tokens）
stream boolean 否 true 走 Responses SSE（response.created / response.output_text.delta / response.completed）
tools array 否 Responses 风格自定义 function tools。web_search、file_search、computer_use 等 OpenAI hosted tools 不支持

非流式示例

curl https://chat.nexusvai.xyz/functions/v1/api-gateway/v1/responses \

  -H "Content-Type: application/json" \

    "input": [

Codex CLI 接入

Codex CLI 是 OpenAI 官方的终端编码助手，默认使用 OpenAI Responses API。 在 ~/.codex/config.toml 中添加一个自定义 provider 即可指向 Cancri。 

model = "gpt-5.3-codex"
model_provider = "cancri"

[model_providers.cancri]
name = "Cancri"
base_url = "https://chat.nexusvai.xyz/functions/v1/api-gateway/v1"
wire_api = "responses"
env_key = "CANCRI_API_KEY"

设置环境变量后启动：

export CANCRI_API_KEY="cancri_sk_YOUR_KEY"
codex
注意：provider id 可以任意命名（这里用 cancri），但务必与 model_provider 保持一致。 不要直接修改 [model_providers.openai]，那是内置 OpenAI provider，不是自定义网关。

Claude Code 接入

Claude Code 是 Anthropic 官方的终端编码助手。只需设置两个环境变量即可指向 Cancri： 

export ANTHROPIC_BASE_URL="https://chat.nexusvai.xyz/functions/v1/api-gateway"
export ANTHROPIC_API_KEY="cancri_sk_YOUR_KEY"
claude
Base URL 不要带 /v1。 Claude Code 启动后会自动在 ANTHROPIC_BASE_URL 后面追加 /v1/messages 和 /v1/messages/count_tokens；填成 .../api-gateway/v1 会形成重复路径。

启动后 Claude Code 会自动拉取 /v1/models（检测到 anthropic-version 头时会返回 Anthropic 格式），并调用 /v1/messages/count_tokens 估算上下文长度。模型选择器里显示的条目以 Claude Code 自身过滤规则为准。

认证方式：默认使用 ANTHROPIC_API_KEY（对应 x-api-key 头）。 如果你的企业代理要求 Authorization: Bearer，可使用 ANTHROPIC_AUTH_TOKEN； 两者同时存在时，Claude Code 以 ANTHROPIC_API_KEY 优先。

OpenCode 接入

sst/opencode 使用 AI SDK 的 provider 机制。 在 ~/.config/opencode/opencode.json 或项目根目录的 opencode.json 中添加自定义 provider： 

{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "cancri": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Cancri",
      "options": {
        "baseURL": "https://chat.nexusvai.xyz/functions/v1/api-gateway/v1",
        "apiKey": "cancri_sk_YOUR_KEY"
      },
      "models": {
        "gpt-5.4": {},
        "claude-sonnet-4-6": {},
        "deepseek-v4-pro": {},
        "gemini-3.1-pro": {}
      }
    }
  }
}
provider 选择：默认用 @ai-sdk/openai-compatible（走 /v1/chat/completions）。 如果你需要调用 Responses 路径的模型（如 Codex 默认的 gpt-5.3-codex），按 OpenCode 官方文档改用 @ai-sdk/openai。

OpenClaw 接入

openclaw/openclaw 通过 models.providers 添加自定义 provider。编辑 ~/.openclaw/openclaw.json 或项目根目录的 openclaw.json。

模型 ID 规则：在 provider 的 models 数组里使用 Cancri Canonical ID（不带 provider 前缀）； 在 agents.defaults.model.primary 中引用时，加上 provider id 前缀，如 cancri/claude-sonnet-4-6。

配置 Anthropic 兼容 provider（Base URL 不带 /v1）：

{
  "env": { "CANCRI_API_KEY": "cancri_sk_YOUR_KEY" },
  "agents": {
    "defaults": {
      "model": { "primary": "cancri/claude-sonnet-4-6" }
    }
  },
  "models": {
    "mode": "merge",
    "providers": {
      "cancri": {
        "baseUrl": "https://chat.nexusvai.xyz/functions/v1/api-gateway",
        "apiKey": "${CANCRI_API_KEY}",
        "api": "anthropic-messages",
        "models": [
          { "id": "claude-sonnet-4-6", "name": "Claude Sonnet 4.6" },
          { "id": "claude-opus-4-6", "name": "Claude Opus 4.6" }
        ]
      }
    }
  }
}

如需调用 OpenAI 兼容协议模型（如 gpt-5.4），再追加一个 provider：

{
  "models": {
    "mode": "merge",
    "providers": {
      "cancri-oai": {
        "baseUrl": "https://chat.nexusvai.xyz/functions/v1/api-gateway/v1",
        "apiKey": "${CANCRI_API_KEY}",
        "api": "openai-responses",
        "models": [
          { "id": "gpt-5.4", "name": "GPT 5.4" },
          { "id": "gpt-5.3-codex", "name": "GPT 5.3 Codex" }
        ]
      }
    }
  }
}

Aider 接入

Aider 底层使用 LiteLLM，支持 OpenAI 兼容端点。 Aider 的模型名格式是 openai/<model-id>，其中 openai/ 是 LiteLLM 的 provider 前缀， 实际发往网关的模型 ID 会去掉该前缀。

客户端接入常见问题

Q: 报错 503 Service Unavailable 并带代码 "api_paused" 是怎么回事？

A: 这是 API 维护状态。维护期间 /v1/models 仍可读取模型列表，但推理写接口会返回 503 api_paused 并附带 Retry-After 头。这是平台级状态，换 Key 或换客户端无法解除，请等待维护结束。

Q: 付费账户与免费账户的 API 限制有何不同？

A: 按账户档位区分：
• 并发： Free 单 Key 最多 2 个进行中请求；Paid 不限。
• 频次： Free 为 10 次/分、60 次/小时、1000 次/天；Paid 为 60 次/分、600 次/小时、50000 次/天。
此外，模型队列、福利池与维护状态会单独生效。

Q: 报错 404 model_not_found 如何解决？

A: 请确保客户端填写的模型 ID 与 /v1/models 返回的完全一致（大小写、连字符都不能错）。部分第三方客户端会自行转换模型名，请在模型设置中手动输入 Cancri Canonical ID（如 gpt-5.4、claude-opus-4-6）。

Q: API 支持图片和视频生成吗？

A: 不支持。图像生成 (/v1/images/generations) 和视频生成 (/v1/videos/generations) 仅对网页版开放，使用公网 API Key 调用会返回 403 endpoint_disabled。

Q: API Key 泄露了怎么办？

A: 立即到 Keys 管理页 撤销该 Key，然后重新生成并替换客户端配置。已撤销的 Key 会立刻失效，无法找回。

配额机制

Cancri 模型分为 FREE 与 PAID 两档（见 模型广场 每张卡片右上角的 badge）。FREE 档对付费用户始终免费；对免费用户优先从全站共享池扣费， 共享池耗尽且无加油包时才会被阻断。PAID 档对免费用户提供有限的试用额度，对付费订阅用户按月度配额计费。订阅分三档： Pro（¥9.9 / 30 天 / 2000 万 token）、 Pro+（¥29 / 30 天 / 8000 万 token，解锁 Claude Opus 全系）、 Pro Max（¥99 / 30 天 / 3 亿 token，全模型 + 图像视频）。 另有加油包（¥10 / ¥50 / ¥200，永不过期），可在月度配额耗尽后续接使用。

积分与 token 的关系

网页端用「积分」、API 用「token」，但两者共享同一个钱包，换算固定： 

1 积分 = 10,000 token

实际扣减 token = 有效 token 数 × 模型权重
扣减积分 = 扣减 token ÷ 10,000
  • 网页端：额度、加油包都按积分显示（Pro = 2000 积分 = 2000 万 token）。
  • API 平台：本文档、Keys 页、用量统计一律使用原始 token，不做积分折算。
  • 同一钱包：网页聊天与 API Key 调用扣的是同一份月度配额 + 加油包余额，只是显示单位不同。

免费用户的付费模型试用规则

  • 全站共享池： 每月 1 亿 token（按折算后的有效 token 计），所有免费用户共享。 每月 1 号 00:00（UTC+8）重置。池内余额耗尽后，如账号还有加油包余额则优先扣加油包继续放行； 加油包余额也为 0 时，当月所有免费用户调用付费模型都会返回 429 free_pool_exhausted，直到下月初。
  • 每日个人限额： 每个免费用户每天有 15 次 付费模型试用额度 （UTC+8 自然日，每天 00:00 重置）。试用额度用满后，如有加油包余额可继续用加油包调用付费模型； 无加油包时返回 429 daily_paid_limit_reached。
  • 失败不计数： 上游返回 HTTP 4xx/5xx 的失败请求会自动退还额度，不计入 15 次/日，也不扣共享池。
  • 滚动 Token 窗口： 免费用户额外受两层时间窗口限制： 5 小时内累计 ≤ 100,000 token，7 天内累计 ≤ 500,000 token（含网页端与 API 合计）。 任一窗口超限返回 429 token_window_5h_exceeded 或 token_window_week_exceeded。 付费用户不受此限制。详见 Token 窗口。
  • 部分模型需付费档： gpt-5.5、gpt-5.5-high、gpt-5.4-mini 仅 Pro 及以上可用，免费用户调用返回 403 model_pro_required，不计入共享池与每日 15 次。
  • Claude Opus 系列： claude-opus-4-5、claude-opus-4-6、 claude-opus-4-6-thinking 等 vip 级模型仅 Pro+ 及以上可用， 免费与 Pro 用户调用返回 403 model_pro_plus_required。
    老用户豁免： 在特定日期前订阅的 Pro 用户，当前订阅周期内可能保留 Opus 调用权限 （以账户状态中的 is_grandfathered 标志为准），续费后按新档位规则执行。

付费订阅用户的月度配额

  • 套餐决定额度： Pro = 2000 万 token / 30 天；Pro+ = 8000 万 / 30 天； Pro Max = 3 亿 / 30 天。每次成功调用扣除「有效 token 数 × 模型权重」（见下方权重表）。
  • 订阅周期重置： 付费订阅按激活后的 30 天周期重置，不是固定日历日期。 重置在你发起请求或查询额度时触发。周期内续费只延长有效期，不会立刻清零配额。
  • 加油包接续： 本周期套餐配额耗尽后自动从加油包余额扣减；两者都为 0 时返回 429 monthly_quota_exhausted。
  • 失败不扣： 与免费用户相同，上游返回 4xx/5xx 的失败请求会自动退还额度。

每个模型有一个成本档位，最终扣减 = 有效 token 数 × 权重。具体权重在 模型广场 每张卡片的价格区域可见。下表是常见档位参考：

档位权重典型模型

token 折算公式

每次成功调用的有效 token 数按上游返回的 usage 字段折算。缓存命中按 10% 计价： 

有效 token 数
  = (输入 token - 缓存命中 token) × 1.0   // 普通输入全价
  + 缓存命中 token              × 0.1   // 缓存命中 1 折
  + 输出 token                  × 1.0;  // 输出全价

最终扣减 = 有效 token 数 × 模型权重

字段映射：OpenAI 协议读取 usage.prompt_tokens、 usage.completion_tokens、 usage.prompt_tokens_details.cached_tokens； Anthropic 协议读取 usage.input_tokens、 usage.output_tokens、 usage.cache_read_input_tokens（首次写入缓存的 cache_creation_input_tokens 按全价）。 流式 SSE 取最后一帧的 usage 字段；若上游未返回 usage，则按已输出文本估算 output_tokens ≈ 字符数 / 4。

升级、续期与档位变更

以下是常见档位变更场景的处理规则。

1. Pro 没到期，买 Pro+（升级）会怎样？

立即生效，按剩余天数补差价，不延长到期日。 升级后订阅档位变为 Pro+，剩余每一天都按 Pro+ 计费，但到期日保持不变。 已消耗 token 不清零、不分段，只是分母变大。

补差价公式： (目标档月价 − 当前档月价) ÷ 30 × 剩余天数，最低 ¥1。 例如还剩 28 天的 Pro 升 Pro+：约 ¥17.83。

升级后配额按比例折算：不是直接给满额，而是 目标档满配额 × 剩余天数 / 30。 例如剩 20 天从 Pro 升 Pro+，配额约为 5334 万，不是 8000 万。

边界： 订阅已过期时升级会被拒；当前档 ≥ 目标档时也不适用升级。

1b. 剩余天数不足 7 天还能补差价升级吗？

不能。 剩余天数 < 7 天时，必须按目标档全价购买新订阅（提档 + 顺延 30 天）。

2. Pro+ 没到期，买 Pro（更低档）续期会怎样？

被拒绝。 当前订阅有效期内不能用低档激活码延长高档权益。 正确做法是购买当前档或更高档激活码，或等当前订阅到期后再用低档激活码重新激活。

3. 同档位续期（Pro 续 Pro）会怎样？

有效期延长 30 天。 到期日顺延 30 天，已消耗 token 不清零，月度配额保持 2000 万。 当前 30 天周期自然结束后，下次消费或查询额度时重置计数。

4. 老用户（Pro 但保留 Opus 访问）续期后会怎样？

续期后 grandfather 特权清除。 用 Pro 码续 Pro 后，会失去 Opus 调用权，变成普通 Pro（2000 万/月）。 用 Pro+ 码升级后，grandfather 也清除，但获得 Pro+ 明码权益（8000 万 + Opus）。

5. 90 天续期上限是什么？

单次续期后，如果新的到期日超过「当前时间 + 90 天」，会返回 subscription_max_horizon_exceeded。 例如今天 6 月 1 日，订阅已续到 9 月 1 日，则无法再续期。等有效期缩短到 60 天以下后，续期窗口重新打开。 升级不受此限制。

6. 套餐配额耗尽后，加油包怎么扣？

扣费顺序是严格的「套餐配额 → 加油包」：

  1. 每次成功调用先扣月度套餐配额；
  2. 套餐配额耗尽后，自动从加油包余额扣；
  3. 两者都为 0 时返回 429 monthly_quota_exhausted。

加油包永不过期，也不会因订阅到期而清零。对付费用户，加油包只在月度套餐配额耗尽后启用，不能替代套餐配额。 对免费用户，加油包还可在全站共享池或每日 15 次试用额度耗尽后续接使用付费模型。

免费用户滚动 Token 窗口

所有免费用户（网页聊天 + API Key 调用）额外受两层滚动时间窗口限制， 两层窗口同时生效，任一触发即返回 429：

窗口上限含义
5 小时窗口 100,000 token 过去 5 小时内累计消耗的 token 总数（input + output，含所有模型）。超过即拦截，直到最早那笔记录滑出窗口。
7 天窗口 500,000 token 过去 7 天内累计消耗的 token 总数。超过即拦截，直到最早那笔记录满 7 天。

计算方式： 每次成功调用实际消耗的原始 token（input + output 之和，不计模型权重与缓存折扣）会进入窗口。 后续请求前，系统对窗口内记录求和并与上限比对。失败调用不计入窗口。

付费用户不受影响： 订阅用户完全跳过此检查。升级到 Pro 即可解除。

为什么要设两层窗口？

5 小时窗口拦截短时高并发，7 天窗口拦截长期持续高用量。两层叠加，兼顾正常尝鲜与滥用防护。

触达上限后多久恢复？

窗口是滚动的，不是固定时间点重置。例如 5 小时窗口在 14:00 被拦截， 需等到最早那笔记录滑出窗口（如 19:00 后）才能恢复。7 天窗口同理， 最早记录满 7 天后自动过期。

免费档保护机制

免费档的设计目标是在满足正常尝鲜用户的同时，防止个别高用量用户影响整体服务。 以下机制分层生效，任何一层触发都会返回对应的错误码。

1. 全站共享池

所有免费用户共享每月 1 亿 token 预算。池子耗尽后，如有加油包余额则先扣加油包继续放行； 加油包余额也为 0 时，当月所有免费用户调用付费模型都会返回 429 free_pool_exhausted，下月 1 号 00:00（UTC+8）重置。

2. 每日 15 次付费模型试用

每个免费用户每天有 15 次付费模型试用额度。试用额度用满后，如有加油包余额可继续用加油包调用； 无加油包时返回 429 daily_paid_limit_reached， 次日 00:00（UTC+8）重置。失败调用（上游 4xx/5xx）不计入次数。

3. 滚动 Token 窗口

5 小时内 ≤ 100,000 token、7 天内 ≤ 500,000 token。任一窗口超限返回 429。 付费用户不受此限制。详见 Token 窗口。

4. 速率限制

免费用户：10 次/分、60 次/小时、1000 次/天、最多 2 个并发请求。 付费用户：60 次/分、600 次/小时、50000 次/天、无单 Key 并发限制。 详见 速率限制。

5. 模型并发队列

每个模型最多同时服务 3 个免费用户，超出后进入排队。付费用户不排队。

6. 福利模型全局 RPM

标记为「福利」的免费模型（如 GLM Flash、DeepSeek V3.1 等）全站每分钟合计最多 100 次调用。 超限后该分钟内返回 429，下一分钟自动恢复。

7. 档位变更规则

升级需补差价、配额按比例折算、剩余天数 < 7 天需全价购买；有效期内禁止用低档激活码续期； 单次续期最多延伸到当前时间 + 90 天。这些规则共同保证档位设计的公平性。

8. 多账号风控

后台通过设备指纹与 IP 维度检测多账号嫌疑。被标记的账号可能在订单审核时被拒。

总结

免费用户单日有 15 次付费模型试用额度，且受 5h/100K + 7d/500K token 窗口约束； 单月受 1 亿全站共享池约束。试用额度、共享池耗尽后可用加油包余额继续调用； 加油包也为 0 或想解除窗口/排队限制时，订阅 Pro（¥9.9/30 天）即可。

响应头

每个成功响应都会带以下 6 个限流头，客户端可据此预估节奏：

响应头 含义
X-RateLimit-Limit-Minute 当前档位的分钟阈值
X-RateLimit-Remaining-Minute 本分钟剩余调用额度
X-RateLimit-Limit-Hour 当前档位的小时阈值
X-RateLimit-Remaining-Hour 本小时剩余调用额度
X-RateLimit-Limit-Day 当前档位的当日阈值
X-RateLimit-Remaining-Day 今天剩余调用额度

撞限后的 429 响应额外带：

  • Retry-After：等多少秒后再重试
  • X-RateLimit-Scope：哪一道防线被撞（per_minute / per_hour / per_day）
并发与模型排队不记在响应头里。 超过并发上限或模型 lane 已满时， 会以 concurrent_limit_exceeded 或 model_queue_full （见下一节）拒接，请按错误码描述决定重试或换模型。

429 识别速查

拿到 429 时按 error.code 区分原因：

  • rate_limit_exceeded → 账户总闸（per-minute/hour/day）被触发， 结合 X-RateLimit-Scope 决定退避；可以同模型重试。
  • concurrent_limit_exceeded → 并发上限（free=2）已用尽， 等已有请求结束后再发新请求。Paid 不会触发此码。
  • model_queue_full → 当前模型免费通道满员，响应体里的 queue_position 给出排位。建议等 10~30 秒重试、换一个模型，或升级到 Paid。
  • upstream_rate_limit → 该模型当前繁忙。建议直接换模型，短时间同模型重试通常无效。
推荐退避策略：首次等待 1 秒，之后按 2 倍指数退避（2s、4s、8s、16s）。优先使用响应中的 Retry-After 头。

模型繁忙与上游故障

当某个模型或上游线路暂时不可用时，网关会自动把流量切到同模型的其它可用线路。 如果所有线路都不可用，会返回 upstream_rate_limit 或 upstream_error。

  • 这些错误是模型级问题，与你的 API Key 无关。
  • 模型不会从 /v1/models 列表中移除。

常见问题

三个端点我该用哪个？

  • 通用聊天优先用 /v1/chat/completions——OpenAI-compatible 工具覆盖面最广。

CLI 模型选择器里看不到我想要的模型？

CLI（特别是 Claude Code）启动时会拉一次 /v1/models，名字必须跟那 一份列表对得上。直接 curl /v1/models 看一下，或到 模型广场 查可用 ID；不要照搬 Anthropic / OpenAI 官方 的版本号（比如 claude-3-5-sonnet-20241022 这边没有）。 Claude Code 的 gateway discovery 还会按客户端规则过滤显示项；非 Claude 命名模型 需要看客户端是否允许手动指定。

tool calling（function calling）支持吗？

支持自定义 function 工具定义与工具调用往返。OpenAI hosted tools 例如 web_search / file_search / computer_use 不属于公开 API 能力；本页不承诺这些字段的稳定行为，客户端不要依赖它们。
