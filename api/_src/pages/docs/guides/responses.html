--- title: Responses description: 用 OpenAI Responses 协议调用模型，适合 Codex CLI 等默认使用该协议的客户端。 ---

POST /v1/responses 兼容 OpenAI Responses 协议。Codex CLI 等客户端默认使用它；用 OpenAI 官方 SDK 时调用 client.responses.create。可用模型与 Chat Completions 相同。完整的参数与响应结构见 API 参考。

与 Chat Completions 相比，主要是字段名不同：input 对应 messages，instructions 对应 system 消息，max_output_tokens 对应 max_tokens。

Codex CLI 默认使用这个协议（配置项 wire_api = "responses"），接入步骤见编程工具。

生成回复

import os
from openai import OpenAI

client = OpenAI(
    base_url="https://cn.nexusvai.xyz/v1",
    api_key=os.environ["CANCRI_API_KEY"],
)

response = client.responses.create(
    model="gpt-6-astra",
    instructions="你是一个简洁的助手。",
    input="用一句话解释什么是行级安全。",
    max_output_tokens=256,
)
print(response.output_text)
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://cn.nexusvai.xyz/v1",
  apiKey: process.env.CANCRI_API_KEY,
});

const response = await client.responses.create({
  model: "gpt-6-astra",
  instructions: "你是一个简洁的助手。",
  input: "用一句话解释什么是行级安全。",
  max_output_tokens: 256,
});
console.log(response.output_text);
curl https://cn.nexusvai.xyz/v1/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $CANCRI_API_KEY" \
  -d '{
    "model": "gpt-6-astra",
    "instructions": "你是一个简洁的助手。",
    "input": "用一句话解释什么是行级安全。",
    "max_output_tokens": 256
  }'

模型生成的内容在 output 数组里：

{
  "id": "resp_...",
  "object": "response",
  "created_at": 1762480000,
  "model": "gpt-6-astra",
  "status": "completed",
  "output": [
    {
      "id": "msg_...",
      "type": "message",
      "status": "completed",
      "role": "assistant",
      "content": [
        { "type": "output_text", "text": "行级安全是一种按行控制谁能读写数据的数据库策略。", "annotations": [] }
      ]
    }
  ],
  "usage": { "input_tokens": 28, "output_tokens": 19, "total_tokens": 47 }
}

output 里可能不止一项：模型公开推理过程时，message 前面会先有一个 reasoning 项；调用工具时会有工具调用项。不要假设文本一定在 output[0].content[0].text，用 SDK 提供的 output_text 汇总文本更稳妥。

status 为 incomplete 时，说明回答被输出上限截断，可以调大 max_output_tokens。

输入格式

input 可以是一个字符串（等同于一条用户消息），也可以是消息项组成的数组：

{
  "model": "gpt-6-astra",
  "instructions": "你是一个简洁的助手。",
  "input": [
    { "role": "user", "content": "推荐一本入门编程的书。" },
    { "role": "assistant", "content": "《Python 编程：从入门到实践》。" },
    {
      "type": "message",
      "role": "user",
      "content": [{ "type": "input_text", "text": "它适合完全没有基础的人吗？" }]
    }
  ]
}
  • 消息项的 content 可以是字符串，也可以是内容块数组。支持 input_text、output_text 和 input_image（image_url 传图片 URL 或 base64 data URL）。
  • instructions 会作为系统提示放在所有输入之前。
  • 工具调用往返使用 function_call 与 function_call_output 项，见工具。
  • 输入里的 reasoning 项会被忽略。

多轮对话

NexusVAI 不在服务端保存对话状态。previous_response_id、store 等字段不生效，要进行多轮对话，每次都把完整历史放进 input：

history = [{"role": "user", "content": "推荐一本入门编程的书。"}]
first = client.responses.create(model="gpt-6-astra", input=history)

history.append({"role": "assistant", "content": first.output_text})
history.append({"role": "user", "content": "它适合完全没有基础的人吗？"})
second = client.responses.create(model="gpt-6-astra", input=history)
print(second.output_text)

只传 previous_response_id 而不带历史时，请求不会报错，但模型看不到之前的对话。

流式输出

设置 stream: true，响应以 Responses 事件流返回。每个事件的数据都带 type 和递增的 sequence_number：

stream = client.responses.create(
    model="gpt-6-astra",
    input="写一首关于秋天的四行诗。",
    stream=True,
)
for event in stream:
    if event.type == "response.output_text.delta":
        print(event.delta, end="", flush=True)
const stream = await client.responses.create({
  model: "gpt-6-astra",
  input: "写一首关于秋天的四行诗。",
  stream: true,
});
for await (const event of stream) {
  if (event.type === "response.output_text.delta") process.stdout.write(event.delta);
}
事件含义
response.created响应开始，status 为 in_progress。
response.output_item.added / response.output_item.done一个输出项（消息、推理或工具调用）开始与结束。
response.content_part.added / response.content_part.done消息中的一个内容块开始与结束。
response.output_text.delta / response.output_text.done增量文本与完整文本。
response.reasoning_summary_text.delta / .done模型公开的推理文本。
response.function_call_arguments.delta / .done函数调用参数的增量与完整值。
response.completed响应完成，附带最终的 output 与 usage。
response.incomplete / response.failed响应被截断或生成失败，原因见流式输出中的错误。

推理强度

用 reasoning.effort 调整推理模型思考的深度：

response = client.responses.create(
    model="gpt-6-astra",
    reasoning={"effort": "high"},
    input="证明根号 2 是无理数。",
)
print(response.output_text)
  • 可选值为 none、minimal、low、medium、high、xhigh、max。minimal 按 low 处理，none 表示不设置。GPT 系列模型收到其他值时返回 400 invalid_request_parameter。
  • 推理强度只会传给已验证支持该参数的模型（主要是 GPT 系列）；其他模型会忽略这个字段，使用默认行为。
  • 模型公开的推理文本以 reasoning 输出项返回，内容在 summary 的 summary_text 块中。

结构化输出

用 text.format 要求模型按 JSON Schema 输出。网关会把它转换为 Chat Completions 的 response_format 交给模型，是否严格遵守 Schema 取决于模型：

{
  "model": "gpt-6-astra",
  "input": "提取这句话中的人名和城市：小王上周去了杭州。",
  "text": {
    "format": {
      "type": "json_schema",
      "name": "extraction",
      "strict": true,
      "schema": {
        "type": "object",
        "properties": {
          "name": { "type": "string" },
          "city": { "type": "string" }
        },
        "required": ["name", "city"],
        "additionalProperties": false
      }
    }
  }
}

也可以使用 {"type": "json_object"}。text.verbosity 不生效。

工具

在 tools 中定义 type: "function" 的函数工具。模型调用工具时，output 中会出现 function_call 项；你执行函数后，把结果作为 function_call_output 项连同历史一起发回：

import json

tools = [{
    "type": "function",
    "name": "get_weather",
    "description": "查询指定城市的当前天气",
    "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"],
    },
}]
history = [{"role": "user", "content": "北京现在天气怎么样？"}]

response = client.responses.create(model="gpt-6-astra", input=history, tools=tools)
for item in response.output:
    if item.type == "function_call":
        args = json.loads(item.arguments)
        result = {"city": args["city"], "weather": "晴", "temperature_c": 18}  # 换成你的实现
        history.append({"type": "function_call", "call_id": item.call_id,
                        "name": item.name, "arguments": item.arguments})
        history.append({"type": "function_call_output", "call_id": item.call_id,
                        "output": json.dumps(result, ensure_ascii=False)})

final = client.responses.create(model="gpt-6-astra", input=history, tools=tools)
print(final.output_text)
  • 本地工具。Codex 使用的 shell、local_shell、apply_patch 和 custom 工具会正确传给模型，模型的调用以对应的输出项返回，由客户端在本地执行。
  • 托管工具。NexusVAI 不在服务端执行 web_search、file_search、code_interpreter、computer_use_preview、mcp、image_generation 等托管工具。传入这些工具时，模型可能发起相应的调用，但需要你的客户端自己处理。

支持的参数

网关只读取下表中的字段，其他字段会被忽略。完整说明见 API 参考。

参数说明
model必填。NexusVAI 模型 ID。
input必填。字符串或输入项数组。
instructions系统提示。
max_output_tokens输出 token 上限，也接受 max_tokens。省略时按该模型的最大输出 token 数。也用于预占 TPM，见速率限制。
temperature、top_p采样参数，必须是非负数。
stream为 true 时以事件流返回。
tools、tool_choice、parallel_tool_calls工具定义与选择策略。
reasoning.effort推理强度，见推理强度。
text.format结构化输出，见结构化输出。
service_tier只接受省略、"auto" 或 "default"，其他值返回 400。

与 OpenAI 的差异

  • 没有服务端状态：previous_response_id、store、background、conversation 不生效。
  • 不执行托管工具，也不支持文件检索与向量库。
  • usage 只包含 input_tokens、output_tokens、total_tokens。
  • 错误使用 OpenAI 的错误格式，见错误码。
