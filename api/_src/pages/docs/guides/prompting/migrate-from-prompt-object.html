--- title: 从提示词对象迁移 description: 将托管提示词对象迁移为应用侧的版本化模板，并用 NexusVAI API 发送内联请求。 tab: models lead: false ---

NexusVAI API 不支持托管的 prompt 对象或 prompt_id。从其他服务迁移时，把模板和版本移到你自己的代码中，将渲染结果通过 instructions 和 input 发送给 Responses API。

迁移前：记录提示词对象

保存当前版本使用的规则、消息角色、模板变量和代表性测试。只拿到旧 ID 时，先从原服务取回模板；不要把旧 ID 当成 NexusVAI 模型 ID。

迁移后：在代码中生成请求

  1. 把固定指令放在有版本的模块，将任务动态值作为函数参数。
  2. 校验参数类型，把用户提供的数据和应用规则分开。
  3. 使用本地维护的模板生成请求，不在请求体中传旧提示词 ID。

使用 Codex 协助迁移

可按 Codex CLI 接入指南配置工具，再请它找出传递提示词 ID 的调用点。审核生成的补丁，确认变量和消息角色没有变化，并用固定测试集比较输出。

变化内容

提示词版本随应用发布，而不由 API 管理。更新模板时同时更新测试；功能开关或配置可以用于选择应用侧的模板版本。

示例

import os
from openai import OpenAI

client = OpenAI(base_url="https://cn.nexusvai.xyz/v1", api_key=os.environ["CANCRI_API_KEY"])
instructions = "你是支持助手。先总结问题，再给出一个建议；不要假定账单已修改。"

def draft_reply(issue: str) -> str:
    response = client.responses.create(
        model="gpt-6-astra",
        instructions=instructions,
        input=issue,
    )
    return response.output_text

print(draft_reply("客户询问如何核对本月账单。"))

收益

模板、评审和测试放在同一处，更容易定位模型行为的变化。下一步了解如何管理提示词版本。

OpenAI 正在弃用 API 中可复用的提示词对象。自 2026 年 6 月 3 日起，提示词创建功能将不再被推荐，v1/prompts 计划于 2026 年 11 月 30 日下线。当前时间线请参阅弃用说明页。

要摆脱 OpenAI API 平台中的 Prompts，请把提示词内容从托管的 prompt 对象中移出，放进你的应用代码。这样你能更好地控制评审、测试、部署和版本管理。

func main() {
	client := openai.NewClient()
	response, err := client.Responses.New(context.Background(), responses.ResponseNewParams{
		Prompt: responses.ResponsePromptParam{
			// 替换为你已发布的提示词 ID。
			ID:      "pmpt_123",
			Version: openai.String("1"),
			Variables: map[string]responses.ResponsePromptVariableUnionParam{
				"customer_name": {OfString: openai.String("Acme")},
				"issue":         {OfString: openai.String("billing question")},
			},
		},
	})
	if err != nil {
		panic(err)
	}
	fmt.Println(response.OutputText())
}

使用 Codex 迁移

使用 OpenAI Developers 插件和 OpenAI Docs 技能，可以自动完成迁移，并加快基于 OpenAI API 的开发。

$openai-docs 更新这个项目，把提示词存放在代码中，不再使用 prompts 对象

变化内容

不再在 API 请求中引用已保存的提示词对象，而是把提示词文本存放在代码库中，并在 Responses API 调用里把生成的消息直接作为 input 传入。

  • 把提示词内容移入源代码，让提示词的修改与产品逻辑走同样的评审和发布流程。
  • 用函数参数替代提示词变量，让动态值在应用中显式且有类型。
  • 在 Responses API 调用中通过 input 传入消息，不再使用 prompt 对象。
  • 把版本管理交给代码仓库，使用 git 提交、PR 评审，以及测试或评估。
  • 静态内容放前面，动态内容放后面，以保留提示缓存的收益，因为缓存命中依赖于完全相同的前缀。

收益

工程上的控制力更强：提示词与产品代码放在一起，修改经由 PR 评审，测试和评估可以在 CI 中运行，发布或实验可以通过你自己的配置或功能开关管理。

不要把提示词零散地写在代码库各处。建一个小的 prompts/ 模块，把每个提示词保存为一个具名的构建函数，并添加轻量的评估样例，让提示词修改与产品逻辑一样经过评审。
