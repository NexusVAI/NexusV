--- title: Messages（Anthropic） description: 用 Anthropic Messages 协议调用模型，适合 Claude Code、Anthropic SDK 与 OpenClaw。 ---

POST /v1/messages 兼容 Anthropic Messages 协议，适用于 Claude Code、官方 Anthropic SDK、OpenClaw 等客户端。model 不限于 Claude 系列：claude-sonnet-5.5、gpt-6-astra、deepseek-v4-flash 都可以通过这个端点调用。完整的参数与响应结构见 API 参考。

Base URL 填 https://cn.nexusvai.xyz，不带 /v1：Anthropic SDK 会自己拼接 /v1/messages。

发送消息

import os
from anthropic import Anthropic

client = Anthropic(
    base_url="https://cn.nexusvai.xyz",
    api_key=os.environ["CANCRI_API_KEY"],
)

message = client.messages.create(
    model="claude-sonnet-5.5",
    max_tokens=1024,
    system="你是一个简洁的助手。",
    messages=[{"role": "user", "content": "用一句话解释什么是行级安全。"}],
)
for block in message.content:
    if block.type == "text":
        print(block.text)
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  baseURL: "https://cn.nexusvai.xyz",
  apiKey: process.env.CANCRI_API_KEY,
});

const message = await client.messages.create({
  model: "claude-sonnet-5.5",
  max_tokens: 1024,
  system: "你是一个简洁的助手。",
  messages: [{ role: "user", content: "用一句话解释什么是行级安全。" }],
});
for (const block of message.content) {
  if (block.type === "text") console.log(block.text);
}
curl https://cn.nexusvai.xyz/v1/messages \
  -H "Content-Type: application/json" \
  -H "x-api-key: $CANCRI_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "claude-sonnet-5.5",
    "max_tokens": 1024,
    "system": "你是一个简洁的助手。",
    "messages": [{"role": "user", "content": "用一句话解释什么是行级安全。"}]
  }'
 
{
  "id": "msg_...",
  "type": "message",
  "role": "assistant",
  "model": "claude-sonnet-5.5",
  "content": [
    { "type": "text", "text": "行级安全是一种按行控制谁能读写数据的数据库策略。" }
  ],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": { "input_tokens": 28, "output_tokens": 19 }
}

stop_reason 的取值：end_turn（正常结束）、max_tokens（达到输出上限）、tool_use（模型要调用工具）。

密钥可以放在 x-api-key 或 Authorization: Bearer 请求头中。anthropic-version 由 SDK 自动发送；网关不校验它的值。

系统提示与多轮对话

system 可以是字符串，也可以是 text 块数组。多轮对话时，把之前的 user 与 assistant 消息按顺序放进 messages：

message = client.messages.create(
    model="claude-sonnet-5.5",
    max_tokens=1024,
    system="你是一个简洁的助手。",
    messages=[
        {"role": "user", "content": "推荐一本入门编程的书。"},
        {"role": "assistant", "content": "《Python 编程：从入门到实践》。"},
        {"role": "user", "content": "它适合完全没有基础的人吗？"},
    ],
)

流式输出

设置 stream: true，响应以 Anthropic 的 SSE 事件返回。Claude Code 默认使用流式输出。

with client.messages.stream(
    model="claude-sonnet-5.5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "写一首关于秋天的四行诗。"}],
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
const stream = await client.messages.create({
  model: "claude-sonnet-5.5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "写一首关于秋天的四行诗。" }],
  stream: true,
});
for await (const event of stream) {
  if (event.type === "content_block_delta" && event.delta.type === "text_delta") {
    process.stdout.write(event.delta.text);
  }
}

事件顺序为：message_start → content_block_start → content_block_delta（若干个）→ content_block_stop → message_delta → message_stop。文本增量的 delta.type 为 text_delta，工具参数增量为 input_json_delta。生成中途失败时会收到 error 事件，见流式输出中的错误。

扩展思考

你可以用 thinking 或 output_config.effort 要求模型思考得更深入：

{
  "model": "claude-sonnet-5.5",
  "max_tokens": 16000,
  "thinking": { "type": "enabled", "budget_tokens": 8000 },
  "messages": [{ "role": "user", "content": "证明根号 2 是无理数。" }]
}
  • 网关把它换算成推理强度，只传给已验证支持该参数的模型；其他模型使用默认行为。
  • output_config.effort 优先，可选 low、medium、high、xhigh、max。
  • 只给 thinking.budget_tokens 时按预算分档：低于 4,096 为 low，低于 16,384 为 medium，低于 32,768 为 high，其余为 max。thinking.type 为 adaptive 时由模型自行决定。

响应中不会出现 thinking 块。模型公开的推理文本以普通 text 块返回，位于回答之前、单独成块；流式时同样是一个单独的 text 内容块。只想展示回答时，请按块区分，不要直接拼接所有文本。

工具调用

用 tools 定义工具（name、description、input_schema）。模型要调用工具时，stop_reason 为 tool_use，content 中有 tool_use 块；你执行后把结果作为 tool_result 块放进下一条 user 消息：

import json

tools = [{
    "name": "get_weather",
    "description": "查询指定城市的当前天气",
    "input_schema": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"],
    },
}]
messages = [{"role": "user", "content": "北京现在天气怎么样？"}]

response = client.messages.create(
    model="claude-sonnet-5.5", max_tokens=1024, tools=tools, messages=messages,
)
if response.stop_reason == "tool_use":
    messages.append({"role": "assistant", "content": response.content})
    results = []
    for block in response.content:
        if block.type == "tool_use":
            result = {"city": block.input["city"], "weather": "晴", "temperature_c": 18}  # 换成你的实现
            results.append({
                "type": "tool_result",
                "tool_use_id": block.id,
                "content": json.dumps(result, ensure_ascii=False),
            })
    messages.append({"role": "user", "content": results})
    final = client.messages.create(
        model="claude-sonnet-5.5", max_tokens=1024, tools=tools, messages=messages,
    )
  • tool_choice 支持 auto、any、none 和 {"type": "tool", "name": "..."}。
  • tool_result 的内容只能是文本（字符串或 text 块）。
  • 不支持 web_search 等 Anthropic 内置的服务端工具，只支持自定义工具。

图片输入

向支持视觉的模型发送图片时，在 user 消息中使用 image 块，source.type 为 base64 或 url：

{
  "role": "user",
  "content": [
    { "type": "image", "source": { "type": "url", "url": "https://example.com/photo.jpg" } },
    { "type": "text", "text": "这张图里有什么？" }
  ]
}

支持的内容块

位置支持的块
systemtext
user 消息text、image（base64 或 url）、tool_result
assistant 消息text、tool_use

其他块（如 document、PDF、thinking、redacted_thinking）无法无损转换，请求会在扣费前被拒绝，返回 400 unsupported_anthropic_content，message 中指出出错块的位置。

计算 token

POST /v1/messages/count_tokens 接受与 /v1/messages 相同的请求体，返回输入 token 数的估算值。Claude Code 会自动调用它来管理上下文，你不需要手动配置。

curl https://cn.nexusvai.xyz/v1/messages/count_tokens \
  -H "Content-Type: application/json" \
  -H "x-api-key: $CANCRI_API_KEY" \
  -d '{
    "model": "claude-sonnet-5.5",
    "messages": [{"role": "user", "content": "你好"}]
  }'
# {"input_tokens": 12}

这个端点不计费、不占用 RPM 与 TPM，每把密钥每分钟最多调用 600 次。返回值是本地估算，可能与实际计费的输入 token 数略有差异。

支持的字段

字段说明
model必填。NexusVAI 模型 ID，与其他端点共用同一份模型目录。
messages必填。对话历史，支持的内容块见上表。
max_tokens输出 token 上限。Anthropic SDK 要求必填；网关不强制，省略时按该模型的最大输出 token 数。也用于预占 TPM，见速率限制。
system系统提示，字符串或 text 块数组。
stream为 true 时返回 SSE 事件。
temperature、top_p采样参数，必须是非负数。
stop_sequences停止序列。
tools、tool_choice自定义工具与选择策略。
thinking、output_config.effort推理强度，见扩展思考。

其他字段（如 top_k、metadata、cache_control）不会生效。

与 Anthropic 的差异

  • 提示缓存。请求中的 cache_control 不生效；支持缓存的模型会自动缓存前缀，命中部分按实际命中量享受折扣。见提示缓存。
  • 思考内容。不返回 thinking 块与签名，推理文本以 text 块返回。
  • usage。只包含 input_tokens 与 output_tokens，不包含缓存读写的 token 数。
  • 错误格式。多数错误使用 Anthropic 格式 {"type": "error", "error": {...}}；但鉴权、请求体大小、参数校验等在路由前完成的检查返回 OpenAI 格式 {"error": {...}}。解析时请两种都兼容，见错误格式。
