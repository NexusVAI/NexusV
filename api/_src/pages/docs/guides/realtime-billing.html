--- title: 计费与限制 description: 实时语音的价格、分段预扣方式、按档位的会话限制，以及服务端何时结束会话。 tab: realtime ---

实时语音按会话时长计费，后端费用另计，都从账户余额中扣除。服务端分段预扣语音费，会话结束后按实际秒数结算。

实际单价以会话开始时 cancri.session.created 中 pricing 返回的数值为准。

扣费方式

  • 按会话时长，而不是说话时长。从 session.started 到会话结束，每一秒都计费，包括双方都沉默的时间。不用时请及时发送 session.close。
  • 分段预扣。会话开始前预扣 30 秒（¥0.27）；本段还剩约 10 秒时预扣下一段；结束后按实际秒数多退少补。余额连一段都不够时，会话不会开始。
  • 计费秒数。以 session.closed 中的 usage.seconds 为准，向上取整。连接异常断开、拿不到最终值时，取最后一次 usage.seconds 与服务端计时中较大的一个。
  • 没开始不收费。认证失败、参数被拒、余额不足、上游连接失败等在 session.started 之前结束的会话，预扣金额全部退回。
  • 后端按回答结算。官方后端每结束一次回答（response.completed 等带 usage 的终态事件），按其 usage 扣费一次；联网按实际搜索次数扣费。每轮回答都会带上此前的对话作为输入，所以长会话的输入 token 会逐轮增加。
  • 余额用完。续段预扣失败时，你会收到 cancri.session.closing（reason 为 insufficient_balance，带 closes_in_seconds）。已预付的时长用完后连接关闭，关闭码为 4402。

速率限制

实时语音按会话限制，而不是按请求：同时进行的会话数、每分钟新建的会话数，以及单个会话的最长时长。档位与 API 速率限制的口径相同，取累计充值档位与有效套餐档位中较高的一个；套餐对应的档位为 Go = T1、Plus = T2、Pro = T3。

  • 限额按账户计算，同一账户的所有 Key 共享；团队 Key 计入团队。
  • 充值或开通套餐后，新档位可能需要几分钟才生效，不需要重新创建 Key。
  • 超出限制时，握手响应带有 X-Cancri-Live-Tier、X-Cancri-Live-Max-Concurrent、X-Cancri-Live-Max-Duration（秒）和 Retry-After 头。
  • 全站同时在线的会话数也有上限。服务繁忙时，握手返回 503 live_capacity_exhausted，请按 Retry-After 稍后重试。

会话何时结束

除了你主动发送 session.close，服务端会在以下情况结束会话。结束前会发送 cancri.session.closing，其中的 reason 就是下表的值。

reason触发条件
max_duration达到本档的单会话最长时长。需要更长的对话时，在客户端自动开启新会话，可以用 session.input 带上历史。
idle_timeout连续 90 秒（以 limits.idle_timeout_seconds 为准）没有转写、没有后端回答，也没有 session.input_audio.* 以外的客户端事件。只发送音频（包括静音）不算活动。
insufficient_balance余额不足以预扣下一段。已预付的时长用完后关闭，关闭码为 4402。
billing_unavailable计费服务暂时不可用，已预付的时长用完后结束。
key_revoked会话期间 Key 被停用或删除。服务端在每次续段前检查。
banned会话期间账户被封禁。
upstream_closed / upstream_error上游连接中断。按已用秒数结算。
start_timeout连接后 20 秒内没有发送 session.start。

服务端关闭连接时，WebSocket 关闭码为 1000（余额不足时为 4402），关闭原因与 reason 相同。服务更新时，进行中的会话也可能断开，同样按已用秒数结算；建议客户端在非主动关闭时自动重连。

降低费用

  • 不说话时尽快发送 session.close：沉默的时间同样计费。
  • 不需要联网时，在官方后端里传 tools: []，关闭默认的联网搜索。
  • 把 reasoning.effort 设为 none 或 low。
  • 只需要语音交互、回答由自己的程序生成时，使用只买语音层。
