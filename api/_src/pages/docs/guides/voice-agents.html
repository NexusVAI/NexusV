语音智能体让用户通过说话向应用提问并完成任务。NexusVAI API 提供 GPT-Live 作为全双工语音层：它负责听和说，应用可以按需要选择推理和工具后端。

选择合适的架构

方式适用场景
默认后端先验证语音交互；使用默认后端完成推理和支持的工具调用。
站内模型需要特定模型的文本能力；在会话中指定站内模型。
客户端委托已有文本智能体、业务规则或工具；由你的应用处理后端任务，再把结果返回给语音层。

配置细节见会话与后端模式。工具真正执行前，应由你的应用检查参数、权限以及是否需要人工确认。

构建全双工语音智能体

让语音层继续听取用户更正，把检索、规则判断和事务操作留给后端。把说话风格写入语音指令，把业务约束放在后端；不要让语音确认替代业务系统中实际执行的结果。

构建语音到语音的智能体

从实时 API 入门开始，在 WebSocket 会话中分别处理输入音频、回复音频和转写事件。暂不支持 WebRTC。

构建串联式语音工作流

如果必须审核或转换中间文本，可以把语音识别、文本处理和语音合成拆成三个环节。NexusVAI 的 Responses API 可用于中间的文本推理环节；独立转写与合成接口不在本站公共 API 的开放端点中。

评估语音智能体

  1. 选取有代表性的场景；写明预期回复、允许调用的工具和应用最终状态。
  2. 测试噪声、口音、语言切换、用户打断和后端超时。分别记录会话中断、听错内容和业务执行失败。
  3. 对照转写、工具结果与实际应用状态；用人工听取补充对自然度和停顿的评价。

测量延迟

分别记录收到委托、后端请求开始、第一个有用结果、回复音频到达和实际播放的时间。只改变一个因素，比较相同场景的中位数和第 95 百分位数。

语音智能体的工作流

语音改变交互方式，但权限、审核、工具参数校验和可观测性仍应由应用管理。设计工具时参考函数调用往返的模式，语音事件则以实时事件为准。
