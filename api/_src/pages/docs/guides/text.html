使用 OpenAI API，你可以像在 ChatGPT 中一样，用大语言模型根据提示生成文本。模型几乎能生成任何类型的文本回复，例如代码、数学公式、结构化的 JSON 数据或接近人类的散文。

像这样直接请求模型生成文本时，请使用 Responses API。

import OpenAI from "openai";
const client = new OpenAI();

const response = await client.responses.create({
  model: "gpt-6-astra",
  input: "Write a one-sentence bedtime story about a unicorn.",
});

console.log(response.output_text);

package main

import (
	"context"
	"fmt"

	"github.com/openai/openai-go/v3"
	"github.com/openai/openai-go/v3/responses"
)

func main() {
	client := openai.NewClient()

	resp, err := client.Responses.New(context.TODO(), responses.ResponseNewParams{
		Model: "gpt-6-astra",
		Input: responses.ResponseNewParamsInputUnion{OfString: openai.String("Say this is a test")},
	})
	if err != nil {
		panic(err.Error())
	}

	fmt.Println(resp.OutputText())
}
import com.openai.client.OpenAIClient;
import com.openai.client.okhttp.OpenAIOkHttpClient;
import com.openai.models.responses.Response;
import com.openai.models.responses.ResponseCreateParams;

public class Main {
  public static void main(String[] args) {
    OpenAIClient client = OpenAIOkHttpClient.fromEnv();

    ResponseCreateParams params =
        ResponseCreateParams.builder().input("Say this is a test").model("gpt-6-astra").build();

    Response response = client.responses().create(params);
    response.output().stream()
        .flatMap(item -> item.message().stream())
        .flatMap(message -> message.content().stream())
        .flatMap(content -> content.outputText().stream())
        .forEach(outputText -> System.out.println(outputText.text()));
  }
}

模型生成的内容数组位于响应的 output 属性中。在这个简单示例中，只有一个输出项，结构如下：

1234567891011121314[
  {
    "id": "msg_67b73f697ba4819183a15cc17d011509",
    "type": "message",
    "role": "assistant",
    "content": [
      {
        "type": "output_text",
        "text": "Under the soft glow of the moon, Luna the unicorn danced through fields of twinkling stardust, leaving trails of dreams for every child asleep.",
        "annotations": []
      }
    ]
  }
]

output 数组中往往不止一项！它可能包含工具调用、推理模型生成的推理 token 数据以及其他项。不要假定模型的文本输出一定位于 output[0].content[0].text。

为方便使用，我们的一些官方 SDK在模型响应上提供了 output_text 属性，它会把模型的全部文本输出合并为一个字符串。如果只想快速取得文本输出，这个属性很有用。

除纯文本外，你还可以让模型以 JSON 格式返回结构化数据，这一功能称为结构化输出。

提示词工程

提示词工程是为模型编写有效指令的过程，目的是让模型稳定地生成符合你要求的内容。

模型生成的内容具有不确定性，因此要得到理想输出，提示既是一门艺术，也是一门科学。不过，只要运用合适的技巧和最佳实践，就能稳定地获得好结果。

有些提示词工程技巧对所有模型都适用，例如合理使用消息角色。但不同模型可能需要不同的提示方式才能获得最佳结果，即使是同一系列的不同快照，结果也可能不同。因此，在构建更复杂的应用时，我们强烈建议：

  • 将生产应用固定到特定的模型快照（例如 gpt-5.5-2026-04-23），以保证行为一致
  • 编写测试和评估套件，衡量提示的行为，以便在迭代、或更换和升级模型版本时持续监控效果

接下来，我们看一看构造提示词时可用的工具和技巧。

选择模型与 API

OpenAI 提供了许多不同的模型，也有多套 API 可供选择。推理模型（例如 gpt-6-astra）的行为与对话模型不同，对不同的提示反应也不同。需要注意的是，推理模型在 Responses API 中表现更好，智能程度也更高。

如果你在开发任何文本生成应用，我们建议使用 Responses API，而不是较早的 Chat Completions API。如果你使用推理模型，迁移到 Responses 尤其有价值。

消息角色与指令遵循

你可以结合 instructions API 参数与消息角色，向模型提供具有不同权威层级的指令。

instructions 参数向模型提供生成回复时的高层指令，包括语气、目标以及正确回答的示例。通过这种方式提供的指令优先于 input 参数中的提示。

import OpenAI from "openai";
const client = new OpenAI();

const response = await client.responses.create({
  model: "gpt-6-astra",
  reasoning: { effort: "low" },
  instructions: "Talk like a pirate.",
  input: "Are semicolons optional in JavaScript?",
});

console.log(response.output_text);

package main

import (
	"context"
	"fmt"

	"github.com/openai/openai-go/v3"
	"github.com/openai/openai-go/v3/responses"
)

func main() {
	client := openai.NewClient()

	response, err := client.Responses.New(context.Background(), responses.ResponseNewParams{
		Model:        "gpt-6-astra",
		Instructions: openai.String("Talk like a pirate."),
		Reasoning: responses.ReasoningParam{
			Effort: responses.ReasoningEffortLow,
		},
		Input: responses.ResponseNewParamsInputUnion{
			OfString: openai.String("Are semicolons optional in JavaScript?"),
		},
	})
	if err != nil {
		panic(err)
	}

	fmt.Println(response.OutputText())
}

package main

import (
	"context"
	"fmt"

	"github.com/openai/openai-go/v3"
	"github.com/openai/openai-go/v3/responses"
)

func main() {
	client := openai.NewClient()

	response, err := client.Responses.New(context.Background(), responses.ResponseNewParams{
		Model: "gpt-6-astra",
		Reasoning: responses.ReasoningParam{
			Effort: responses.ReasoningEffortLow,
		},
		Input: responses.ResponseNewParamsInputUnion{
			OfInputItemList: responses.ResponseInputParam{
				responses.ResponseInputItemParamOfMessage(
					"Talk like a pirate.",
					responses.EasyInputMessageRoleDeveloper,
				),
				responses.ResponseInputItemParamOfMessage(
					"Are semicolons optional in JavaScript?",
					responses.EasyInputMessageRoleUser,
				),
			},
		},
	})
	if err != nil {
		panic(err)
	}

	fmt.Println(response.OutputText())
}

import com.openai.client.okhttp.OpenAIOkHttpClient;
import com.openai.models.Reasoning;
import com.openai.models.ReasoningEffort;
import com.openai.models.responses.EasyInputMessage;
import com.openai.models.responses.ResponseCreateParams;
import com.openai.models.responses.ResponseInputItem;
import java.util.List;

String semicolonsDevMsg = "Talk like a pirate.";

String semicolonsPrompt = "Are semicolons optional in JavaScript?";

ResponseCreateParams params =
    ResponseCreateParams.builder()
        .model("gpt-6-astra")
        .input(
            ResponseCreateParams.Input.ofResponse(
                List.of(
                    ResponseInputItem.ofEasyInputMessage(
                        EasyInputMessage.builder()
                            .role(EasyInputMessage.Role.DEVELOPER)
                            .content(semicolonsDevMsg)
                            .build()),
                    ResponseInputItem.ofEasyInputMessage(
                        EasyInputMessage.builder()
                            .role(EasyInputMessage.Role.USER)
                            .content(semicolonsPrompt)
                            .build()))))
        .reasoning(Reasoning.builder().effort(ReasoningEffort.LOW).build())
        .build();

client.responses().create(params).output().stream()
    .flatMap(item -> item.message().stream())
    .flatMap(message -> message.content().stream())
    .flatMap(content -> content.outputText().stream())
    .forEach(text -> System.out.println(text.text()));

注意，instructions 参数只作用于当前这次回复生成请求。如果你使用 previous_response_id 参数管理对话状态，之前轮次使用的 instructions 不会出现在上下文中。

OpenAI 模型规范描述了模型如何为不同角色的消息赋予不同的优先级。

developeruserassistant

developer 消息是应用开发者提供的指令，优先级高于用户消息。

user 消息是终端用户提供的指令，优先级低于开发者消息。

模型生成的消息使用 assistant 角色。

多轮对话可以由这些类型的多条消息组成，并包含你和模型提供的其他内容类型。进一步了解如何管理对话状态。

可以把 developer 消息和 user 消息类比为编程语言中的函数及其参数。

  • developer 消息提供系统的规则和业务逻辑，相当于函数定义。
  • user 消息提供输入和配置，developer 消息中的指令会作用于这些内容，相当于函数的参数。

在代码中管理提示词版本

把生产环境的提示词存放在应用代码中，而不是创建可复用的提示词对象。由代码管理的提示词可以使用有类型的输入、代码评审、测试以及常规的部署流程来改变模型行为。

OpenAI 正在弃用 API 中可复用的提示词对象。自 2026 年 6 月 3 日起，提示词创建功能将不再被推荐，v1/prompts 计划于 2026 年 11 月 30 日下线。当前时间线请参阅弃用说明页。

对于新的文本生成工作：

  • 把提示词构建函数放在它所服务的功能附近的小模块中。
  • 对客户数据、文件或任务选项等动态值，使用有类型的函数参数或 schema。
  • 把生成的 instructions 和 input 直接传给 Responses API。
  • 修改生产提示词之前，先添加有代表性的样例、测试和评估检查。
  • 通过你的部署系统发布提示词修改；需要分阶段发布时，使用功能开关或配置。

如果你的集成通过提示词 ID 或版本调用已保存的提示词，请参阅提示词对象迁移指南，把该提示词迁移到代码中。
