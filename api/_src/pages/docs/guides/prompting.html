提示是向模型提供输入的过程。输出质量往往取决于你能把提示写到什么程度。

概览

提示既是艺术，也是科学。OpenAI 提供了一些策略和 API 设计决策，帮助你构造有效的提示，并稳定地从模型获得好结果。我们鼓励你多做尝试。

提示工具与技巧

  • 提示缓存：复用稳定的提示前缀，缓存命中时降低延迟和输入 token 费用
  • 提示词工程：学习构造提示词的策略、技巧和工具

优化你的提示词

  • 把整体语气或角色说明放在 system 消息中；把与任务相关的细节和示例放在 user 消息中。
  • 把少样本示例合并成简洁的 YAML 风格或列表块，方便团队浏览和更新。
  • 用清晰的文件夹名映射项目结构，方便同事快速找到提示词。
  • 每次发布时都运行提示词测试和评估用例；尽早发现问题，比在生产环境中修复便宜得多。

在应用中使用提示词

把提示词当作应用代码来对待。把提示词内容保存在具名模块中，用有类型的函数参数构建动态部分，并把提示词修改与它所支持的产品行为放在同一个 PR 中评审。

OpenAI 正在弃用 API 中可复用的提示词对象。自 2026 年 6 月 3 日起，提示词创建功能将不再被推荐，v1/prompts 计划于 2026 年 11 月 30 日下线。当前时间线请参阅弃用说明页。

对于新的工作，不要创建可复用的提示词对象。改为：

  • 把每个生产提示词保存在由代码管理、带版本的辅助模块中，例如 prompts/supportReply.ts。
  • 用有类型的函数参数或经过校验的输入对象替代提示词变量。
  • 通过 input 和 instructions，把生成的消息直接传给 Responses API。
  • 用测试、有代表性的样例和评估检查覆盖提示词修改，并让它们随部署流程一起运行。
  • 利用 git 历史、PR 评审、发布标签和功能开关来评审、发布、比较和回滚提示词修改。

如果你的 API 请求已经在使用提示词 ID 或提示词版本，请参阅迁移指南，把这些提示词移入代码。
