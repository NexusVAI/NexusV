--- title: 计费与余额 description: API 按用量从余额扣费：请求开始前按预估金额预扣，结束后按实际 usage 结算，多退少补。 ---

NexusVAI API 按用量计费。账户有余额就可以调用已定价的模型，每次调用从账户的 API 余额扣费；团队密钥从团队余额扣费，见团队。

按量计费

每个模型单独定价，价格见价格与模型页的模型卡片：

  • 多数模型按输入与输出 token 计费，单价以「元 / 百万 token」表示。
  • 命中缓存的输入 token 默认按输入单价的 1 折计算（Claude Opus 5.5 含 Thinking 为 3 折），见提示缓存。
  • 部分能力按次计费，每次调用收取固定费用。

扣费以响应中的 usage 为准，三种协议的计费规则相同。

预扣与结算

  1. 预扣。请求发给模型之前，按「预估输入 token × 输入单价 + 输出上限 × 输出单价」预扣（按次计费的模型预扣单次价格）。输出上限就是你传入的 max_tokens（Responses 为 max_output_tokens）；没传时按该模型的最大输出 token 数。
  2. 余额不足时拒绝。余额低于预估金额时返回 402 insufficient_balance，请求不会发给模型，也不扣费。这个错误带 x-should-retry: false，充值后再试。
  3. 结算。请求结束后按实际 usage 结算，多退少补。实际费用超过预扣、余额又不够补足时，差额记为欠费，通过 GET /v1/balance 的 debt 字段查看。

余额较少时，给请求设置合理的 max_tokens 可以降低预扣金额，避免因为按模型最大输出预扣而收到 402。最终扣费只按实际用量计算，不受这个上限影响。

哪些情况会扣费

情况是否扣费
请求成功按 usage 扣费
返回 4xx 或 5xx 错误不扣费，预扣金额全部退回
流式输出中途被截断，流末尾收到 stream_incomplete_billed按已经产生的 token 扣费
流式输出因模型侧故障中断，收到 model_temporary_failure 或 upstream_stream_interrupted不扣费
请求已发给模型后，你主动断开连接（包括中途停止流式输出）按已经产生的 token 扣费；还没有输出时只收输入部分
请求发出后 2 秒内、模型还没开始响应时断开不扣费

这样设计是因为模型收到请求后就开始消耗算力。需要取消时，尽量在请求刚发出时取消。

提示缓存

支持缓存的模型会自动缓存请求的前缀。命中缓存（cache read）的输入 token 默认按输入单价的 1 折计费（Claude Opus 5.5 含 Thinking 为 3 折，各模型的缓存命中价见价格页），按每个请求的实际命中量结算，你不需要做任何配置。

  • 命中条件。请求前缀必须完全一致、长度达到模型的最低要求，而且缓存只保留几分钟（Anthropic 模型默认约 5 分钟）。单次请求或前缀不断变化的请求不会命中。把固定不变的内容（系统提示、工具定义、长文档）放在前面、把变化的内容放在后面，更容易命中。
  • cache_control 不生效。Messages 请求中的 cache_control 会被忽略，缓存由模型自动完成。
  • usage 不显示缓存命中。出于安全考虑，响应的 usage 不返回缓存命中的 token 数，按其他服务的字段格式检测缓存的第三方工具可能显示「无缓存」。缓存折扣已计入每次调用的扣费，可以用 GET /v1/balance 返回的 cost 或控制台的用量页核对。

免费模型与未定价模型

  • 免费模型不扣余额，但计入每 24 小时 1 亿 token 的免费额度，并受速率限制约束。见免费模型与免费额度。
  • 未定价的模型不可调用，返回 402 model_not_priced。请换用其他模型。

API 余额与套餐

  • API 调用只从 API 余额扣费。网页对话与 Cancri Code 的套餐额度不能用于 API。
  • 反过来，如果你订阅了套餐且当期套餐额度已用完，网页对话与 Cancri Code 超出的部分会按量从同一份余额扣除。
  • 团队密钥只从团队余额扣费，不会动用成员的个人余额。

充值

在控制台的账单页购买充值卡，兑换卡密后立即到账。充值后继续使用原来的密钥即可。

累计充值达到门槛时，速率限制档位会自动提升，见速率限制。代金券与赠送额度不计入累计充值。

查看余额与扣费

调用 GET /v1/balance 可以查询账户余额、欠费、当前密钥的限额，以及当前密钥最近的调用记录与每次扣费。也可以在控制台的账单页和用量页查看。
