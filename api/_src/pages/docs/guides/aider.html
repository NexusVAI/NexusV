--- title: Aider description: 通过 LiteLLM 的 OpenAI 兼容模式，在 Aider 中使用 NexusVAI 的模型。 tab: coding ---

Aider 是一个终端里的结对编程工具，通过 LiteLLM 支持 OpenAI 兼容端点。接入 NexusVAI 时，模型名写成 openai/<模型 ID>：openai/ 是 LiteLLM 的 provider 前缀，发送请求时会被去掉。

前提条件

  • 已安装 Aider。
  • 一个 NexusVAI API 密钥，可以在控制台创建，并保存在环境变量 CANCRI_API_KEY 中。

用命令行参数启动

aider \
  --model openai/gpt-6-astra \
  --openai-api-base https://cn.nexusvai.xyz/v1 \
  --openai-api-key "$CANCRI_API_KEY"

用配置文件

不想每次都输入参数时，在项目根目录创建 .aider.conf.yml：

model: openai/gpt-6-astra
openai-api-base: https://cn.nexusvai.xyz/v1
openai-api-key: cancri_sk_...

.aider.conf.yml 写有 Key 时，不要把它提交到代码仓库。

选择模型

编码任务推荐 openai/gpt-6-astra；需要 Claude 时使用 openai/claude-opus-5.5。实际请求的模型 ID 分别是 gpt-6-astra 和 claude-opus-5.5，其他可用模型见 GET /v1/models。

验证配置

在 Aider 中提一个简单的问题，然后查询这个 Key 最近的调用：

curl "https://cn.nexusvai.xyz/v1/balance?limit=5" \
  -H "Authorization: Bearer $CANCRI_API_KEY"

recent_usage.data 里应该出现刚才的请求，model 为不带 openai/ 前缀的模型 ID。字段说明见验证请求是否到达 NexusVAI。

排查问题

现象可能的原因解决方法
请求没有出现在 /v1/balance 的记录里模型名缺少 openai/ 前缀，请求没有按 OpenAI 兼容方式发往 openai-api-base。写成 openai/gpt-6-astra 这样的形式。
404 model_not_found前缀后面的模型 ID 不在 GET /v1/models 的列表中。改成列表中的 id。
421 relay_path_not_supportedopenai-api-base 少了末尾的 /v1。填 https://cn.nexusvai.xyz/v1。
401 invalid_api_keyKey 填错或已撤销。在控制台确认 Key 状态。
