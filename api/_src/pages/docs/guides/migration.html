--- title: 从其他平台迁移 description: 从 OpenAI、Anthropic 或其他 OpenAI 兼容服务切换到 NexusVAI，通常只需改 Base URL、密钥和模型 ID。 ---

NexusVAI 兼容 OpenAI 与 Anthropic 的请求格式，所以从 OpenAI 官方、Anthropic 官方、One API / New API 或其他兼容服务迁移时，一般不需要改业务代码。这篇指南列出需要替换的三项配置、迁移后要检查的地方，以及与原平台的差异。

需要替换的配置

  1. Base URL。OpenAI 协议的 SDK 和工具填 https://cn.nexusvai.xyz/v1；Anthropic 协议的 SDK 和工具（Anthropic SDK、Claude Code）填 https://cn.nexusvai.xyz，不带 /v1。
  2. API 密钥。换成以 cancri_sk_ 开头的 NexusVAI 密钥，在控制台创建，无需审核。
  3. 模型 ID。换成 NexusVAI 的模型 ID，取值见模型或 GET /v1/models。不要沿用原平台的型号快照（如 gpt-4o、claude-3-5-sonnet-20241022）或其他服务的自定义别名。

请求体不用改：OpenAI 兼容客户端照常发送 model、messages 等字段，Anthropic 兼容客户端照常发送 model、max_tokens、messages。

只能使用 API 密钥。网页登录会话不能代替 cancri_sk_ 密钥。不要把浏览器 Cookie 或登录令牌填进客户端。

配置对照

在客户端里找到「Base URL」「API Host」或「OpenAI API Base」之类的字段，按下表替换：

原配置NexusVAI 配置
OpenAI 官方 https://api.openai.com/v1Base URL 改为 https://cn.nexusvai.xyz/v1；密钥改为 cancri_sk_...；模型改为 NexusVAI 模型 ID，如 gpt-6-astra
One API / New API 等 OpenAI 兼容服务把整个地址替换为 https://cn.nexusvai.xyz/v1；密钥与模型 ID 同上
Anthropic 官方 https://api.anthropic.comBase URL 改为 https://cn.nexusvai.xyz（不带 /v1）；模型改为如 claude-sonnet-5.5
环境变量 OPENAI_BASE_URL / ANTHROPIC_BASE_URLCodex、Claude Code、Aider 等命令行工具优先读取环境变量，按上面的地址设置即可

代码改动示例

以官方 SDK 为例，只有创建客户端的几行需要改：

import os
from openai import OpenAI

# 之前：client = OpenAI()
client = OpenAI(
    base_url="https://cn.nexusvai.xyz/v1",
    api_key=os.environ["CANCRI_API_KEY"],
)

response = client.chat.completions.create(
    model="gpt-6-astra",  # 之前：gpt-4o
    messages=[{"role": "user", "content": "你好"}],
)
import os
from anthropic import Anthropic

# 之前：client = Anthropic()
client = Anthropic(
    base_url="https://cn.nexusvai.xyz",
    api_key=os.environ["CANCRI_API_KEY"],
)

message = client.messages.create(
    model="claude-sonnet-5.5",  # 换成 NexusVAI 模型 ID
    max_tokens=1024,
    messages=[{"role": "user", "content": "你好"}],
)

在编程工具与 IDE 中配置

常见工具都提供自定义 Base URL 的入口：

  • Cursor：Settings → Models → Override OpenAI Base URL。
  • Cline、Continue：扩展设置中的 OpenAI Compatible 选项，或 Continue 的配置文件。
  • Cherry Studio、Chatbox、LobeChat、SillyTavern：提供商选择 OpenAI 兼容。
  • Claude Code、Codex CLI、Aider、OpenCode、OpenClaw：通过环境变量或配置文件设置。

逐个工具的步骤见编程工具。

部分 IDE（如 Cursor）的 Agent 与行内补全可能走厂商自己的服务，自定义 Base URL 通常只对对话生效。如果某个功能仍在请求原来的地址，可以改用命令行智能体或编辑器扩展。

与原平台的差异

  • 托管工具与文件。不支持 OpenAI 的托管工具（网页搜索、文件检索、代码解释器、computer use）、文件与向量库；自定义函数工具可以使用，部分模型支持。
  • Responses 没有服务端状态。previous_response_id、store 不生效，多轮对话需要每次带上完整历史。见 Responses 指南。
  • Messages 的思考内容。模型的推理内容以普通 text 块返回，不会出现带签名的 thinking 块；cache_control 不生效。见 Messages 指南。
  • usage 只给计数。响应中的 usage 不包含缓存命中的 token 数；缓存折扣已体现在扣费里。
  • 图像与视频生成不对 API 开放。调用 /v1/images/generations 或 /v1/videos/generations 返回 403 endpoint_disabled。
  • 速率限制按账户计算。网页、桌面端、Bot 与 API 共用一组 RPM 和 TPM，见速率限制。

迁移后检查

  1. 调用 GET /v1/balance（不计费），确认 Base URL 与密钥有效。
  2. 用一个模型 ID 发送最短的请求，确认返回 200 且带有 usage。
  3. 如果你的应用用到流式输出或工具调用，分别测试一次，确认请求发往 NexusVAI。
  4. 遇到 401 invalid_api_key、404 model_not_found 或 403 endpoint_disabled 时，对照错误码排查。
