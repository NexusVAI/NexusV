--- title: 错误码 description: 错误响应使用标准 HTTP 状态码，error.code 给出具体原因。请按 error.code 处理错误。 ---

请求失败时，NexusVAI 返回标准的 HTTP 状态码，并在响应体的 error.code 中给出具体原因。同一个状态码可能对应多种原因，所以处理错误时请以 error.code 为准；它是稳定的机器可读标识，error.message 只供人阅读，可能调整。

错误格式

OpenAI 协议端点（/v1/chat/completions、/v1/responses）以及 /v1/models、/v1/balance 使用 OpenAI 的错误格式：

{
  "error": {
    "message": "Invalid API key. Provide a valid key as Bearer token (Authorization) or x-api-key header.",
    "type": "authentication_error",
    "code": "invalid_api_key"
  }
}

Anthropic 协议端点（/v1/messages）的错误大多使用 Anthropic 格式，Anthropic SDK、Claude Code 与 OpenClaw 可以直接解析：

{
  "type": "error",
  "error": {
    "type": "permission_error",
    "message": "Account balance insufficient. Please top up and retry.",
    "code": "insufficient_balance"
  }
}

/v1/messages 上，鉴权、请求体大小、参数校验和密钥级限制这些在路由前完成的检查，返回的是 OpenAI 格式（没有外层的 "type": "error"）。404 模型不存在时返回 Anthropic 格式，但只有 error.type（not_found_error），没有 error.code。自己解析错误时，两种格式都要兼容：先读 error.code，没有时再读 error.type。

错误码列表

请求错误（400、404、413）

HTTPerror.code说明
400无（null）请求体不是合法的 JSON，或缺少 model。type 为 invalid_request_error。
400invalid_request_parameter参数不合规，error.param 指出字段：service_tier 不是省略、auto 或 default；GPT 系列的推理强度不在允许范围；max_tokens、max_output_tokens、temperature、top_p 不是非负数。见请求参数校验。
400unsupported_anthropic_content/v1/messages 的请求中有不支持的内容块（如 document、thinking）。见 Messages 指南。
400image_input_unsupported该模型只接受文本输入。去掉图片，或换用支持视觉的模型。
400context_too_long部分按次计费的模型对单次请求的上下文另有上限，错误信息会给出上限和本次的估算值。缩短上下文后再试。
400invalid_content_lengthContent-Length 请求头的值无效。
400invalid_limitGET /v1/balance 的 limit 不是 0–100 的整数。
404model_not_foundmodel 不在可用列表中。用 GET /v1/models 核对模型 ID，大小写与连字符必须完全一致。
404无（null）端点不存在，例如 /v1/embeddings。
413payload_too_large请求体超过 10 MB。缩短上下文或拆分请求。

认证与权限（401、403）

HTTPerror.code说明
401invalid_api_key缺少密钥、格式错误、密钥不存在或已撤销。见认证与 API 密钥。
403account_suspended账户已被限制使用。如有疑问请联系我们。
403endpoint_disabled该端点不对 API 开放（如 /v1/images/generations、/v1/videos/generations），仅网页版可用。
403model_ide_only该模型只在 Cancri Code 桌面端可用，不对 API 开放。
403model_not_in_whitelist这把密钥设置了模型白名单，所选模型不在其中。
403model_not_in_group这把密钥限定了模型分组，所选模型不在该分组中。
401 / 403upstream_auth_error该模型暂时不可用，与你的 API 密钥无关。换用其他模型。

余额与计费（402）

HTTPerror.code说明
402insufficient_balance余额不足以支付本次请求的预估费用（团队密钥看团队余额）。不可重试，充值后再试。见预扣与结算。
402model_not_priced该模型尚未定价，暂不可调用。换用其他模型。

限额（429）

HTTPerror.code说明
429rate_limit_exceeded超出 RPM 或 TPM，按 Retry-After 等待后重试。也用于 GET /v1/balance 超过每分钟 30 次。见速率限制。
429request_too_large单次请求的预占 token 超过本档 TPM 的 4 倍。不可重试，缩短上下文或调低 max_tokens。
429free_plan_exhausted免费额度已用完，error.resets_at 给出重置时间。不可重试，见免费额度。
429key_token_quota_exhausted
key_request_quota_exhausted		这把密钥的累计 token 或累计请求数上限已用完。不可重试，改用其他密钥。
429upstream_rate_limit所选模型暂时繁忙，与你的账户限额无关。稍后重试或换模型。
429auth_rate_limited同一 IP 短时间内多次使用不存在的密钥。按 Retry-After 等待，并修正密钥配置。

服务与模型（5xx）

HTTPerror.code说明
随模型侧而定upstream_error模型侧返回了错误，状态码沿用模型侧的状态码，可能是 4xx 或 5xx。常见原因是模型暂时不可用，也可能是请求超出了该模型的限制（如上下文长度）。稍后重试，或换用其他模型。
502upstream_error模型返回了无效的响应，本次不扣费。稍后重试。
503api_pausedAPI 维护中。/v1/models 仍可读取，推理接口暂停，响应带 Retry-After: 86400。
503maintenance_mode系统维护中，所有 API 端点暂停服务，包括 /v1/models。
503service_unavailable认证或余额服务暂时不可用，与你的密钥无关。稍后重试。
503quota_check_failed计费服务暂时不可用，本次未扣费。稍后重试。
503model_group_unavailable密钥限定了模型分组，但暂时无法读取分组信息。稍后重试。
503hyperdrive_quota_exhausted服务暂时降级。按 Retry-After 等待后重试。
504upstream_error模型在 180 秒内没有开始响应。非流式请求需要在这段时间内生成完毕，输出较长时改用流式输出，或调低 max_tokens 后重试。

流式输出中的错误

流式响应开始后，HTTP 状态码已经是 200，之后出现的错误会以事件的形式出现在流里：

协议错误的形式
Chat Completions流的末尾出现一个带 error 字段的 chunk，随后是 data: [DONE]。
Responses以 response.failed 结束，原因在 response.error.code；或以 response.incomplete 结束，原因在 response.incomplete_details.reason（如 upstream_interrupted、upstream_truncated）。
Messages收到 error 事件，原因在 error.code。

Chat Completions 流里常见的错误码：

error.code含义是否计费
model_temporary_failure模型暂时繁忙，没有生成有效内容。error.retry_after_seconds 给出建议的等待时间。不计费，可以稍后重试或换模型
upstream_stream_interrupted模型侧连接在回复中途断开，回答不完整。不计费
stream_incomplete_billed回答不完整，已按实际产生的 token 计费（error.billed 为 true）。已计费；重试会产生一次新的计费请求
 
data: {"id":"chatcmpl-...","object":"chat.completion.chunk","error":{"message":"该模型当前繁忙，请稍后或切换其他模型。","type":"api_error","code":"model_temporary_failure","retry_after_seconds":30}}

data: [DONE]

模型暂时不可用

所选模型暂时繁忙或不可用时，返回 upstream_rate_limit、upstream_auth_error 或 upstream_error（包括超时的 504），流式时可能是 model_temporary_failure。

  • 这类错误与你的 API 密钥、余额和账户档位无关。
  • 模型不会因此从 GET /v1/models 中移除。
  • 按 Retry-After 退避后重试，或换用其他模型。见准备备用模型。

重试

  • 响应带 Retry-After 时，按其取值（秒）等待后重试。
  • 没有 Retry-After 的 429 与 5xx，使用指数退避，并加入随机抖动。
  • 不要重试不可重试的错误：402 insufficient_balance、429 request_too_large、429 free_plan_exhausted、429 key_token_quota_exhausted、429 key_request_quota_exhausted。它们的响应都带 x-should-retry: false，官方 OpenAI 与 Anthropic SDK 读到这个响应头就不会自动重试。
  • 其他 4xx 说明请求本身有问题，修正后再发。
