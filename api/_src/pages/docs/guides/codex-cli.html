--- title: Codex CLI description: 在 config.toml 中添加一个自定义 provider，让 Codex CLI 通过 Responses 协议使用 NexusVAI 的模型。 tab: coding ---

Codex CLI 是 OpenAI 的终端编程智能体，默认使用 Responses API。你只需要在 ~/.codex/config.toml 里添加一个指向 NexusVAI 的 provider，再把 API 密钥放进环境变量。

前提条件

  • 已安装 Codex CLI。
  • 一个 NexusVAI API 密钥，可以在控制台创建。
  • 一个模型 ID。编码任务推荐 gpt-6-astra，也可以用 GET /v1/models 中的其他模型。

添加 provider

编辑 ~/.codex/config.toml（没有就新建），加入以下内容：

model = "gpt-6-astra"
model_provider = "cancri"

[model_providers.cancri]
name = "NexusVAI"
base_url = "https://cn.nexusvai.xyz/v1"
wire_api = "responses"
env_key = "CANCRI_API_KEY"
字段说明
model默认使用的模型 ID，必须与 GET /v1/models 返回的一致。
model_provider使用哪个 provider。必须与下面 [model_providers.<id>] 中的 id 相同。
name显示名称，可以随意填写。
base_urlhttps://cn.nexusvai.xyz/v1，以 /v1 结尾。
wire_api"responses"，使用 Responses 协议。
env_key保存 API 密钥的环境变量名。

provider id 可以自定义（示例为 cancri），但必须与 model_provider 一致，否则 Codex 仍会把请求发往默认的 provider。不要修改内置的 [model_providers.openai]。

设置密钥并启动

export CANCRI_API_KEY="cancri_sk_..."
codex
$env:CANCRI_API_KEY = "cancri_sk_..."
codex

环境变量要在启动 codex 的同一个终端里生效。长期保存的方法见设置 API 密钥。

Codex 的 shell、apply_patch 等本地工具会被转换成模型能调用的函数，命令和文件修改仍由 Codex 在你的电脑上执行，所以 Agent 模式可以照常使用。

验证配置

在 Codex 中发送一条简短的指令，例如「列出当前目录的文件」。然后查询这个 Key 最近的调用：

curl "https://cn.nexusvai.xyz/v1/balance?limit=5" \
  -H "Authorization: Bearer $CANCRI_API_KEY"

recent_usage.data 的第一条应该是刚才的请求，model 为 gpt-6-astra。字段说明见验证请求是否到达 NexusVAI。

排查问题

现象可能的原因解决方法
401 invalid_api_key启动 Codex 的终端里没有设置 CANCRI_API_KEY，或 env_key 写的变量名不一致。在同一个终端里 echo $CANCRI_API_KEY 确认，再重新启动 codex。
404 model_not_foundmodel 不在 GET /v1/models 的列表里。改成列表中的 id，注意大小写和连字符。
请求没有出现在 /v1/balance 的记录里model_provider 与 provider id 不一致，请求发往了其他服务。检查两处 id 是否相同。
421 relay_path_not_supportedbase_url 少了末尾的 /v1。填 https://cn.nexusvai.xyz/v1。
404，消息为 Not found: /v1/v1/responsesbase_url 多写了一个 /v1。填 https://cn.nexusvai.xyz/v1。

更多问题见客户端常见问题。
