--- title: Chat Completions description: 用 OpenAI Chat Completions 协议生成文本、流式输出、调整推理强度和调用工具。 ---

POST /v1/chat/completions 兼容 OpenAI Chat Completions 协议，是支持的客户端和工具最多的端点，适合大多数场景。你用 OpenAI 官方 SDK 或任何 OpenAI 兼容客户端，把 Base URL 设为 https://cn.nexusvai.xyz/v1 即可调用全部模型。完整的参数与响应结构见 API 参考。

生成回复

传入模型 ID 和消息列表，模型的回答在 choices[0].message.content：

import os
from openai import OpenAI

client = OpenAI(
    base_url="https://cn.nexusvai.xyz/v1",
    api_key=os.environ["CANCRI_API_KEY"],
)

response = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[
        {"role": "system", "content": "你是一个简洁的助手。"},
        {"role": "user", "content": "用一句话解释什么是行级安全。"},
    ],
)
print(response.choices[0].message.content)
import OpenAI from "openai";

const client = new OpenAI({

系统提示与多轮对话

接口是无状态的：模型只看到你这一次发送的 messages。要进行多轮对话，把之前的问答按顺序放进列表，再追加新问题：

  • system：对模型的总体指示，放在最前面。
  • user：用户的输入。
  • assistant：模型之前的回答。
  • tool：工具的执行结果，见工具调用。
messages = [
    {"role": "system", "content": "你是一个简洁的助手。"},
    {"role": "user", "content": "推荐一本入门编程的书。"},
    {"role": "assistant", "content": "《Python 编程：从入门到实践》。"},
    {"role": "user", "content": "它适合完全没有基础的人吗？"},
]
response = client.chat.completions.create(model="deepseek-v4-flash", messages=messages)
messages.append({"role": "assistant", "content": response.choices[0].message.content})

历史越长，输入 token 越多，费用和 TPM 占用也越高。对长对话，可以截断或摘要较早的轮次。

流式输出

设置 stream: true，响应以 Server-Sent Events（SSE）逐块返回：

stream = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[{"role": "user", "content": "写一首关于秋天的四行诗。"}],
    stream=True,
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
    if chunk.usage:
        print("\n", chunk.usage)
const stream = await client.chat.completions.create({
  model: "deepseek-v4-flash",
  messages: [{ role: "user", content: "写一首关于秋天的四行诗。" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
  if (chunk.usage) console.log("\n", chunk.usage);
}
curl https://cn.nexusvai.xyz/v1/chat/completions \
  -N \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $CANCRI_API_KEY" \
  -d '{
    "model": "deepseek-v4-flash",
    "messages": [{"role": "user", "content": "写一首关于秋天的四行诗。"}],
    "stream": true
  }'

每个事件是一行以 data: 开头的 JSON，choices[0].delta.content 是增量文本，最后以 data: [DONE] 结束：

data: {"id":"chatcmpl-...","object":"chat.completion.chunk","model":"deepseek-v4-flash","choices":[{"index":0,"delta":{"role":"assistant","content":"秋"},"finish_reason":null}]}

data: {"id":"chatcmpl-...","object":"chat.completion.chunk","model":"deepseek-v4-flash","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: {"id":"chatcmpl-...","object":"chat.completion.chunk","model":"deepseek-v4-flash","choices":[],"usage":{"prompt_tokens":18,"completion_tokens":42,"total_tokens":60}}

data: [DONE]

网关总是为流式请求开启 stream_options.include_usage。所以每个流在 [DONE] 之前都有一个 choices 为空数组、带 usage 的 chunk。读取 choices[0] 前先判断数组非空。

流式响应还有两点需要处理：

  • 模型长时间思考时，流里会出现以冒号开头的 : keep-alive 注释行，用来保持连接。官方 SDK 会自动忽略。
  • 如果生成中途失败，流的末尾会出现一个带 error 字段的 chunk，随后是 data: [DONE]。错误码与是否计费见流式输出中的错误。

推理模型

用 reasoning_effort 调整推理模型思考的深度。更高的强度通常回答更好，但更慢、输出 token 更多：

response = client.chat.completions.create(
    model="gpt-6-astra",
    reasoning_effort="high",
    messages=[{"role": "user", "content": "证明根号 2 是无理数。"}],
)
print(response.choices[0].message.content)
print(response.usage.completion_tokens_details)
  • GPT 系列模型的 reasoning_effort 只接受 none、low、medium、high、xhigh、max，其他值返回 400 invalid_request_parameter。
  • 其他模型会收到你传入的值，是否生效取决于模型。
  • 推理消耗的 token 计入输出 token，可以在 usage.completion_tokens_details.reasoning_tokens 中查看。
  • 会公开推理过程的模型，把推理文本放在 message.reasoning_content（或 reasoning）字段；流式时出现在 delta 的同名字段中。

工具调用

在 tools 中描述你的函数，模型决定需要时会返回 tool_calls。你在自己的代码里执行函数，把结果以 tool 消息发回，模型再给出最终回答。并非所有模型都支持工具调用，请先在模型页确认。

import json

tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查询指定城市的当前天气",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string", "description": "城市名，例如 北京"}},
            "required": ["city"],
        },
    },
}]
messages = [{"role": "user", "content": "北京现在天气怎么样？"}]

response = client.chat.completions.create(model="gpt-6-astra", messages=messages, tools=tools)
message = response.choices[0].message

if message.tool_calls:
    messages.append(message)
    for call in message.tool_calls:
        args = json.loads(call.function.arguments)
        result = {"city": args["city"], "weather": "晴", "temperature_c": 18}  # 换成你的实现
        messages.append({
            "role": "tool",
            "tool_call_id": call.id,
            "content": json.dumps(result, ensure_ascii=False),
        })
    final = client.chat.completions.create(model="gpt-6-astra", messages=messages, tools=tools)
    print(final.choices[0].message.content)
const tools = [{
  type: "function",
  function: {
    name: "get_weather",
    description: "查询指定城市的当前天气",
    parameters: {
      type: "object",
      properties: { city: { type: "string", description: "城市名，例如 北京" } },
      required: ["city"],
    },
  },
}];
const messages = [{ role: "user", content: "北京现在天气怎么样？" }];

const response = await client.chat.completions.create({ model: "gpt-6-astra", messages, tools });
const message = response.choices[0].message;

if (message.tool_calls) {
  messages.push(message);
  for (const call of message.tool_calls) {
    const args = JSON.parse(call.function.arguments);
    const result = { city: args.city, weather: "晴", temperature_c: 18 }; // 换成你的实现
    messages.push({ role: "tool", tool_call_id: call.id, content: JSON.stringify(result) });
  }
  const final = await client.chat.completions.create({ model: "gpt-6-astra", messages, tools });
  console.log(final.choices[0].message.content);
}

只支持 type: "function" 的自定义工具。OpenAI 的托管工具（网页搜索、文件检索、代码解释器等）不会在服务端执行。

图片输入

向支持视觉的模型发送图片时，把 content 写成内容块数组，图片用 image_url 块传入公开的图片 URL 或 base64 data URL：

{
  "model": "支持视觉的模型 ID",
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "这张图里有什么？" },
        { "type": "image_url", "image_url": { "url": "https://example.com/photo.jpg" } }
      ]
    }
  ]
}

只接受文本的模型收到图片时返回 400 image_input_unsupported。哪些模型支持视觉，见模型页。

常用参数

请求体中的字段会转发给模型。下表列出网关会特别处理的字段，完整参数见 API 参考。

参数说明
model必填。NexusVAI 模型 ID。
messages必填。对话历史，元素包含 role 与 content。
stream为 true 时以 SSE 流式返回，默认 false。网关会自动开启 stream_options.include_usage。
max_tokens / max_completion_tokens输出 token 上限。省略时，网关按该模型的最大输出 token 数补上。这个值也用于预占 TPM，见速率限制。
temperature、top_p采样参数，必须是非负数。取值范围与默认值以模型为准。
tools、tool_choice、parallel_tool_calls函数工具，部分模型支持。
reasoning_effort推理强度。GPT 系列只接受 none 到 max 这 6 个值。
service_tier只接受省略、"auto" 或 "default"，且不会转发给模型；其他值返回 400。

其他 OpenAI 标准参数（如 stop、seed、response_format）原样转发，是否生效取决于模型。

与 OpenAI 的差异

  • 响应只保留标准字段：id 由 NexusVAI 生成，model 返回你请求的模型 ID，没有 system_fingerprint。
  • usage 只包含 prompt_tokens、completion_tokens、total_tokens 和 completion_tokens_details.reasoning_tokens，不包含缓存命中的 token 数。
  • 流式响应总是在结尾附带 usage chunk，并可能夹带 : keep-alive 注释行。
  • 错误使用 OpenAI 的错误格式，error.code 是 NexusVAI 的错误码，见错误码。
