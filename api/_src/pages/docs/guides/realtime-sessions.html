--- title: 会话与后端模式 description: 用 session.start 配置语音层的指令、音频格式和对话历史，并在官方后端、站内模型和只买语音层之间选择。 tab: realtime ---

每个会话都以 session.start 开始。它决定语音层怎么说话、用什么音频格式，也决定由哪个后端回答问题。会话开始后，只有官方后端的参数还能修改，其他设置都固定下来。

配置 session.start

{
  "type": "session.start",
  "session": {
    "model": "gpt-live-1",
    "instructions": "你是一个简洁的中文语音助手。",
    "audio": {
      "format": { "type": "audio/pcm", "rate": 24000 },
      "output": { "voice": "marin" }
    }
  }
}

session.start 必须是第一条事件，且只能发送一次。服务端只接受下表中的字段：未列出的字段会返回 unknown_parameter 并结束会话，而不是被忽略。

字段类型说明
session.modelstring只能是 gpt-live-1，可以省略。
session.instructionsstring语音层的系统提示，用来设定语气、人设和语言，最多 64,000 个字符。省略时使用默认指令：用用户的语言简短自然地回答，需要事实、实时信息、计算或推理时交给后端。填写后按原文使用，不再叠加默认指令。
session.audio.formatobject输入与输出共用的音频格式。{"type": "audio/pcm", "rate": 24000}（默认）或 rate: 16000；电话场景可用 audio/pcmu 或 audio/pcma，rate 为 8000。PCM 为 16 位小端、单声道。
session.audio.output.voicestring音色名，例如 marin。可用音色以 OpenAI 的 GPT-Live 文档为准。
session.inputarray预置的对话历史，最多 128 条。每条只能包含 type（"message" 或省略）、role（developer、user 或 assistant）、content 和 id。
session.storeboolean只能为 false 或省略。
session.triggersarray只能为空数组或省略（不支持 Decisions）。
session.delegationobject后端设置，见选择后端。省略时使用官方后端 GPT-6-Luna，并默认启用联网搜索。
session.delegation.acknowledgement_delay_msinteger委派开始后，等待多少毫秒让语音层先说一句「好的，我查一下」之类的话。取值 0–10000。
event_idstring可选，最多 128 个字符，随 session.start 一起转发给上游。

选择后端

gpt-live-1 只负责听和说。需要回答实质问题时，它发起一次委派，由后端给出答案。cancri.session.created 事件的 mode 字段会告诉你会话最终使用了哪种模式。

模式怎么配置 delegationmode后端费用
官方后端省略；或 type 为 "responses"，responses.model 省略或为 gpt-6-lunaofficialGPT-6-Luna 的 token 与联网次数
站内模型type 为 "responses"，responses.model 为站内模型 idsite按该模型的价格

写了 delegation 时，type 必填，只能是 responses 或 client。

官方后端：GPT-6-Luna

默认模式。GPT-6-Luna 通过 Responses 协议生成答案，可以联网搜索，也可以调用你定义的函数。

{
  "type": "session.start",
  "session": {
    "model": "gpt-live-1",
    "instructions": "你是旅行助手，回答简短。",
    "delegation": {
      "type": "responses",
      "responses": {
        "model": "gpt-6-luna",
        "instructions": "需要实时信息时先联网搜索。",
        "tools": [
          { "type": "web_search" },
          {
            "type": "function",
            "name": "get_order",
            "description": "查订单状态",
            "parameters": {
              "type": "object",
              "properties": { "order_id": { "type": "string" } },
              "required": ["order_id"]
            }
          }
        ],
        "tool_choice": "auto",
        "reasoning": { "effort": "low" },
        "max_output_tokens": 2048
      }
    }
  }
}
delegation.responses 字段说明
model只能是 gpt-6-luna，省略即为它。
instructions后端的系统提示，最多 64,000 个字符。省略时使用默认指令：答案依赖实时或不确定的事实时联网搜索，回答简短（会被朗读出来）。
tools最多 32 个，类型只能是 web_search（按次计费）、function 或 custom（由你执行，没有工具费）。function 和 custom 必须带 name。其他类型返回 live_tool_not_allowed。省略时默认 [{"type": "web_search"}]；传 [] 可关闭联网。
tool_choiceauto、none、required，或指向上述类型的某个工具。省略 tools 时默认为 auto。
parallel_tool_callsboolean。
max_output_tokens整数，16–128000。
reasoning.effortnone、low、medium、high、xhigh 或 max。越高越慢，输出 token 越多，费用也越高。
service_tier只能是 default。不支持 Fast / priority，其他取值返回 live_service_tier_not_allowed。
textobject，含义与 Responses API 相同。

在会话中修改后端

官方后端模式下，可以用 session.update 修改 delegation.responses，同样受上表约束。音色、音频格式、instructions 等其他字段在会话开始后不能修改，会返回 immutable_field_update；把 model 改成 gpt-6-luna 以外的值会返回 live_backend_model_not_allowed。这些错误只拒绝当前这条事件，会话继续。

{
  "type": "session.update",
  "session": {
    "delegation": {
      "responses": { "reasoning": { "effort": "medium" } }
    }
  }
}

处理函数调用

后端调用你的函数时，response.event 里会出现 function_call 输出项。执行完函数后，把结果交回，再让后端继续生成：

ws.send(JSON.stringify({
  type: "response.item.create",
  item: {
    type: "function_call_output",
    call_id: "call_...", // 与 function_call 中的 call_id 相同
    output: JSON.stringify({ status: "已发货" }),
  },
}));
ws.send(JSON.stringify({ type: "response.create" }));

response.item.create 只接受 function_call_output 和 custom_tool_call_output 两种 item，且必须带 call_id。

站内模型做后端

把 responses.model 设为 GET /v1/models 中的任意模型 id。语音层仍是 gpt-live-1，回答交给你选的模型：

{
  "type": "session.start",
  "session": {
    "model": "gpt-live-1",
    "delegation": {
      "type": "responses",
      "responses": {
        "model": "claude-haiku-5.5",
        "instructions": "用中文一两句话回答。",
        "max_output_tokens": 512
      }
    }
  }
}

每次语音层发起委派，服务端会把截至当前的双向转写（最近 60 轮、约 24,000 个字符）整理成对话，用你的 Key 调用一次 /v1/chat/completions，再把答案交给语音层朗读。

  • 只接受 model、instructions 和 max_output_tokens（16–4096，默认 1024）。不支持工具：传入 tools 等其他字段会返回 live_site_backend_unsupported_parameter。需要联网时请使用官方后端。
  • 模型不在 GET /v1/models 中时，会话不会开始（live_backend_model_not_allowed），也不收费。
  • 后端调用和普通 API 调用完全一样：按该模型的价格计费，出现在用量记录里，并受 Key 的模型白名单和额度约束。
  • 每次回答完成后，你会收到 cancri.delegation.completed，里面有模型原文、耗时和 token 数，方便显示或记录。
  • 后端收到的是语音识别出的文字，可能有错字。
  • 同一时间最多处理 2 个回答，超出时语音层会请用户稍等。单次回答最长 90 秒，超时后语音层会请用户再说一次。
  • 站内模型模式不能用 session.update 修改后端，也不能使用 response.* 事件。

只买语音层

如果你已经有自己的 Agent，只缺语音交互，把 delegation.type 设为 client。这种模式只收语音费。

{
  "type": "session.start",
  "session": { "model": "gpt-live-1", "delegation": { "type": "client" } }
}

语音层需要答案时，会发来一个委派事件：

{
  "type": "session.delegation.created",
  "delegation": { "id": "item_9tA2bF3h7K9m2P5q8R1s4", "type": "delegation", "target": "client" }
}

根据转写（session.input_transcript.delta）算出答案后，用同一个 delegation_id 交回：

{
  "type": "session.commentary.append",
  "event_id": "result_1",
  "delegation_id": "item_9tA2bF3h7K9m2P5q8R1s4",
  "content": "订单今天已发货，明天送达。"
}
事件用途
session.commentary.append要说给用户听的结果。语音层可能会转述。
session.thinking.append只给语音层参考、不念出来的进度或事实。content 传 "" 可以取消自动的「好的，我查一下」。
session.instructions.appenddelegation_id 为 null 时，追加一条会话级指令。
  • 同一个委派可以多次追加。每条 content 最多 8,000 个字符；上游对单条的限制约为 500 token，较长的结果请分段发送。
  • delegation_id 是字符串（最多 128 个字符）或 null。
  • 追加成功后会收到对应的确认事件，例如 session.commentary.appended。
  • 这三个事件在官方后端和站内模型模式下也能使用，例如随时补充背景信息。
