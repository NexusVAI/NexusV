图像生成面向网页版，NexusVAI 公共 API 未开放。调用 /v1/images/generations 会返回 403 endpoint_disabled；Responses 也不执行图像生成工具。理解已有图片仍可使用视觉输入。

概览

在 NexusV 对话中选择可用的图像功能。以下图库只使用站内素材，示例提示词用于说明如何描述任务，不保证复现同一张图。

生成图像

用一句话写清主体和场景，再补充光线、色调、构图和画面用途。例如：「为旅行杂志生成一张室内泳池的配图，暖米色墙面、藤椅和从高窗照进来的自然光，无人物和文字。」

编辑图像

如果使用的网页功能支持图片编辑，上传参考图并具体说明改哪一处、保留哪些细节。多次调整时保留原图，用每次的结果与原始需求对照。

限定编辑区域

若使用的编辑工具支持蒙版，可将需要改变的局部标注出来。请求中仍需说明对象、改动和区域外必须保留的内容。

自定义图像输出

尺寸与质量选项

先确定横版、竖版或方形等构图，再选网页可用的分辨率和质量选项。导出前检查文字、边缘、主体比例和背景；更高分辨率不会自动解决构图或拼写错误。

局限性

模型不保证精确拼写、像素级位置、固定人物特征或同一提示词的复现。重要细节请人工检查，所用参考图应有使用权限。

费用与延迟

查看价格

网页图像功能和公共 API 分开计费，网页费用以使用界面为准。公共 API 的 token 费用可以用模型 Token 费用计算器估算，再核对模型定价。

模型可用性

以网页实际提供的选项为准，历史模型名或价格示例不表示当前仍开放。提示词的通用写法见图像提示词。

概览

使用该 API，你可以通过文本提示词使用 gpt-image-2.5-sunburst 和 gpt-image-2.5-flare 生成和编辑图像。对编辑精度要求最高的工作流选择 Sunburst，快速而高质量的日常图像生成选择 Flare。你可以通过两个 API 使用图像生成能力：

Image API

一个 Image API 提供两个端点，各自具有不同的能力：

  • 生成：根据文本提示词从零生成图像
  • 编辑：使用新的提示词修改现有图像，可以是局部或整体

Responses API

一个 Responses API 允许你在对话或多步骤流程中生成图像。它将图像生成作为内置工具提供，并支持在上下文中接收图像输入和输出。

与 Image API 相比，它额外提供：

  • 多轮编辑：通过提示词对图像进行逐步的高保真编辑
  • 灵活输入：可以接收图像 文件 ID 作为输入图像，不仅限于二进制数据

对于可以调用图像生成工具的主线模型，请参见支持的模型。

选择合适的 API

  • 如果你只需要根据一条提示词生成或编辑一张图像，Image API 是最佳选择。
  • 如果你想用 GPT Image 构建可对话、可编辑的图像体验，请选择 Responses API。

使用 Image API 时，直接将 model 设为 gpt-image-2.5-sunburst 或 gpt-image-2.5-flare。使用 Responses API 时，在顶层选择一个支持的主线模型，并在图像生成工具的 model 字段中指定 gpt-image-2.5-sunburst 或 gpt-image-2.5-flare。

两种 API 都可以通过调整质量、尺寸、格式和压缩率来自定义输出。

为确保负责任地使用 GPT Image 模型，你可能需要先在开发者控制台完成API 组织验证。

安全标识符

如果应用面向个人用户，建议在每次图像生成或图像编辑请求中附上稳定且不暴露隐私的 safety_identifier。请对用户名或电子邮件地址取哈希，不要直接发送身份信息，并将标识符长度控制在 128 个字符以内。此字段建议提供，但不是必填项。

Images API 的 user 参数已弃用，请改用 safety_identifier 传递同一个标识符。已有的 user 请求仍受支持。非空的 safety_identifier 优先；如果该参数缺省、为 null 或为空字符串，API 会在提供了 user 时使用它。

生成图像

可以使用 Image API 的 图像生成端点根据文本提示词创建图像，也可以在 Responses API 中使用图像生成工具，在对话中生成图像。

关于自定义输出（尺寸、质量、格式、压缩）的更多信息，请参见下方自定义图像输出一节。

你可以设置 n 参数，在一次请求中同时生成多张图像（默认情况下，API 只返回一张）。

func saveFirstGeneratedImage(response *responses.Response, filename string) {
	for _, output := range response.Output {
		if output.Type != "image_generation_call" {
			continue
		}
		image, err := base64.StdEncoding.DecodeString(output.AsImageGenerationCall().Result)
		if err != nil {
			panic(err)
		}
		if err := os.WriteFile(filename, image, 0o600); err != nil {
			panic(err)
		}
		return
	}
	panic("response did not include an image generation call")
}

多轮图像生成

使用 Responses API，你可以构建涉及图像生成的多轮对话。具体方式有两种：在上下文中提供图像生成调用的输出（也可以只使用图像 ID），或使用 previous_response_id 参数。这样你可以在多轮中反复迭代图像，改进提示词、应用新指令，并随着对话推进不断演进视觉输出。

使用 Responses API 的图像生成工具时，支持的工具模型可以自行选择是生成新图片，还是编辑对话中已有的图片。可选的 action 参数控制这一行为：保持 action: "auto" 让模型决定；设置 action: "generate" 强制每次生成新图片；设置 action: "edit" 则在上下文中有图片时强制编辑。

func outputAsInput(output []responses.ResponseOutputItemUnion) []responses.ResponseInputItemUnionParam {
	input := make([]responses.ResponseInputItemUnionParam, 0, len(output))

		if err := json.Unmarshal([]byte(item.RawJSON()), &converted); err != nil {
			panic(err)
		}
		input = append(input, converted.ToParam())
	}
	return input
}

流式输出

Responses API 和 Image API 都支持流式图像生成。你可以在 API 生成过程中流式接收部分图片，交互体验更好。

你可以调整 partial_images 参数，接收 0 到 3 张部分图片。

  • 对于大于 0 的值，如果完整图片生成得更快，你可能不会收到请求数量的全部部分图片。

func uploadImage(client openai.Client, filename string) string {
	file, err := os.Open(filename)
	if err != nil {
		panic(err)
	}

	uploaded, err := client.Files.New(context.Background(), openai.FileNewParams{File: file, Purpose: openai.FilePurposeVision})

func dataURL(filename string) string {
	image, err := os.ReadFile(filename)
	if err != nil {
		panic(err)
	}

func openImages(names ...string) ([]io.Reader, func()) {
	images := make([]io.Reader, 0, len(names))
	files := make([]*os.File, 0, len(names))
	for _, name := range names {
		file, err := os.Open(name)
		if err != nil {
			closeFiles(files)
			panic(err)
		}
		images = append(images, openai.File(file, name, "image/png"))
		files = append(files, file)
	}
	return images, func() { closeFiles(files) }
}

func closeFiles(files []*os.File) {
	for _, file := range files {
		if err := file.Close(); err != nil {
			panic(err)
		}
	}
}

	}

使用蒙版编辑图像

你可以提供蒙版，指出图像中哪一部分应该被编辑。

使用 GPT Image 蒙版时，会额外向模型发送指令，帮助它按相应方式引导编辑过程。

GPT Image 的蒙版编辑完全由提示词驱动。模型会参考蒙版，但生成结果可能不会完全贴合蒙版的形状。

如果你提供了多张输入图像，蒙版只会应用到第一张图像上。

蒙版要求

要编辑的图像与蒙版必须格式和尺寸相同，且小于 50MB。

蒙版图像必须包含 alpha 通道。如果你使用图像编辑工具制作蒙版，请确保保存时带上 alpha 通道。

你可以通过程序修改黑白图像，为它添加 alpha 通道。

# 3. Then use the mask itself to fill that alpha channel
mask_rgba.putalpha(mask)

# 4. Convert the mask into bytes
buf = BytesIO()
mask_rgba.save(buf, format="PNG")
mask_bytes = buf.getvalue()

# 5. Save the resulting file

with open(img_path_mask_alpha, "wb") as f:

	if err != nil {

	bounds := mask.Bounds()
	withAlpha := image.NewNRGBA(bounds)

			withAlpha.SetNRGBA(x, y, color.NRGBA{R: gray.Y, G: gray.Y, B: gray.Y, A: gray.Y})

自定义图像输出

你可以配置以下输出选项：

  • 尺寸：图像的宽和高（例如 1024x1024、1024x1536）
  • 质量：渲染质量（例如 low、medium、high）
  • 格式：输出文件的格式
  • 压缩：JPEG 和 WebP 格式的压缩程度（0–100%）
  • 背景：透明、不透明或自动选择

size、quality 和 background 均支持 auto，由模型根据提示词自动选择合适的设置。

尺寸与质量选项

gpt-image-2.5-sunburst 和 gpt-image-2.5-flare 新增了 xhigh 和 max 质量档位，默认都使用 auto。早期 GPT Image 模型最高支持 high。

设置 选项
推荐尺寸 1024x1024（正方形）、1536x1024（横向）、1024x1536（纵向）
质量 low, medium, high, xhigh, max, auto

两个模型都支持以 WIDTHxHEIGHT 字符串指定自定义尺寸，例如 1536x864。宽和高都必须是 16 的倍数，宽高比须介于 1:3 与 3:1 之间，任一边均不得超过 3840 像素。总像素数须介于 655,360 与 8,294,400（4K）之间。高于 2560x1440 的分辨率仍属于实验功能。

若需透明背景，请设置 background: "transparent"，并将 output_format 设为 "png" 或 "webp"。

快速出草稿时可用 quality: "low"。制作最终素材时，可以比较更高的质量档位，在图像细节、延迟和费用之间取舍。

输出格式

Images API 返回 Base64 编码的图像数据。默认格式为 png，也可指定 jpeg 或 webp。

使用 jpeg 或 webp 时，还可以用 output_compression 参数设置压缩程度（0–100%）。例如，output_compression=50 表示以 50% 的压缩程度处理图像。

使用 jpeg 比使用 png 更快。对延迟有要求时，可以优先选择 jpeg。

局限性

GPT Image 模型功能强大、用途广泛，但仍有一些需要注意的限制：

  • 延迟：复杂提示词可能需要最多 2 分钟才能处理完毕。
  • 文字渲染：虽然能力已有明显改善，但模型有时仍难以准确放置文字或保持清晰。
  • 一致性：模型可以生成风格一致的图像，但在多次生成中，重复出现的角色或品牌元素偶尔会有视觉差异。
  • 构图控制：虽然模型更能遵循指令，但在结构复杂或对布局要求较高的图像中，仍可能无法精准摆放元素。

内容审核

所有提示词和生成图像均会依照内容政策进行审核。

使用 GPT Image 模型生成图像时，可通过 moderation 参数控制审核的严格程度。该参数支持两个值：

  • auto（默认）：采用标准过滤，限制生成某些可能不适合低龄用户的内容。
  • low：采用较宽松的过滤。

处理被拦截的请求和其他错误

图像生成失败时，按处理其他 API 错误的方式操作：检查 HTTP 状态码或 SDK 异常类型，记录请求 ID，并参阅错误码指南排查认证、配额、限流和服务器错误。对于暂时的限流或服务器错误，可以延长间隔后重试。配额错误或需要修改请求的图像生成错误不应自动重试。

有些图像生成失败可由用户修正，可能返回 error.type = "image_generation_user_error"。如果没有修改提示词或输入图像，不要自动重试。在程序中应使用稳定的 error.code 识别错误类型。

当 error.code = "moderation_blocked" 时，错误响应也可能包含可选的 error.moderation_details 对象：

12345678910{
  "error": {
    "type": "image_generation_user_error",
    "code": "moderation_blocked",
    "moderation_details": {
      "moderation_stage": "input",
      "categories": ["harassment"]
    }
  }
}

moderation_details 对象提供概括性的调试信息，不会暴露分类器的内部标签或分数。

moderation_stage 可以是：

  • input：提示词或其他请求输入触发了拦截。
  • output：生成图像或后续的输出审核环节触发了拦截。
  • unknown：少数难以判定来源时使用的备用值。

categories 包含概括性的公开标签，例如 harassment、self-harm、sexual 或 violence。

对大多数应用而言，面向用户的主要错误提示宜保持通用。moderation_details 可用于开发日志、客服流程、数据分析和简要的修正提示。
