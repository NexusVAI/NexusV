不是每个任务都需要更高的推理强度。先用一组代表性样例测试较快的模型，再决定哪些任务需要更强的推理能力。具体配置请看 NexusVAI API 推理指南。

推理模型与低延迟模型

对固定格式提取、分类等目标明确的任务，优先比较低延迟模型。需要解释模糊需求、变更多个文件或检查相互矛盾的条件时，再测试推理模型。

如何选择

固定任务输入、工具、评分标准和输出要求；同时测任务成功率、首个有用结果的耗时、总用量和失败处理，避免只按名称或单次回答选择模型。

何时使用推理模型

处理模糊任务

要求说明缺失的条件，在关键假设无法确认时先追问。

从大量材料中提取要点

先筛选相关片段，再让模型返回原文位置；核对结论是否有材料支撑。

跨材料找关系

让模型区分已知事实、推断和冲突证据，用原始记录交叉验证。

规划多步骤工作

写明目标、约束和每个阶段的检查点。必要时用推理模型规划，把明确定义的子任务交给更快的模型。

视觉推理

确认模型支持图像输入。在图表和表格上核对关键数值，不把模糊图片上的识别结果当成定论。

审查和调试代码

给出预期行为、失败样例和允许的修改范围，要求返回可重现的问题和回归测试。

评估模型回复

使用明确的评分标准、人工复核样例和反例；不要把另一个模型的评分当成唯一真值。

如何编写提示

  • 用短而明确的指令，先描述任务和成功标准。
  • 用标题或标签分开规则、用户输入和参考材料。
  • 如果输出形式不明确，提供少量输入和预期结果示例。
  • 要求提供可核实的结论、引用或测试，不要求输出内部思考过程。

控制成本并保持准确性

减少无关上下文，限制不必要的重试，只提高困难任务的推理强度。多轮使用 Responses 时由应用传回历史；store 和 previous_response_id 不会替你保留状态。
