--- title: 图像与视觉 description: 通过 NexusVAI API 将图片作为视觉输入，让支持视觉的模型分析、读图和回答问题。 tab: models lead: false ---

用 NexusVAI API 向支持视觉的模型发送图片。模型可以根据图片提取文字、解释图表，也可以结合文字问题描述可见内容。先到模型目录确认视觉能力。

概览

Responses 使用 input_image，Chat Completions 使用 image_url。使用已有客户端时，选择它支持的协议；识别效果取决于模型和输入质量。

生成或编辑图片

这里介绍图片输入，不是图片输出。图像生成与编辑请看网页图像功能；NexusVAI 公共 API 不执行图像生成工具。

分析图片

向模型提供图片输入

使用公开 HTTPS 图片 URL 或自带 MIME 类型的 Base64 data URL；不要使用托管 file_id。下面是两种请求格式。示例地址请换成你自己的图片，并把模型替换为目录中的视觉模型 ID。

{
  "model": "支持视觉的模型 ID",
  "input": [{"role": "user", "content": [
    {"type": "input_text", "text": "这张图里有什么？不确定的部分请注明。"},
    {"type": "input_image", "image_url": "https://example.com/photo.jpg"}
  ]}]
}
{
  "model": "支持视觉的模型 ID",
  "messages": [{"role": "user", "content": [
    {"type": "text", "text": "这张图里有什么？不确定的部分请注明。"},
    {"type": "image_url", "image_url": {"url": "https://example.com/photo.jpg"}}
  ]}]
}

发送请求与读取响应的方法见 Responses 输入或 Chat Completions 图片输入。

图片输入要求

确保图片 URL 可以被读取，且不要在地址里放密钥。对敏感图片先获得授权；格式、尺寸、细节级别和上下文限制以目标模型为准。识别小字时优先裁剪并保留足够分辨率，而不是盲目扩大整张图片。

计算成本

图片会占用输入预算。知道图片的 token 数后，到模型 Token 费用计算器选择模型，把图片 token 计入输入，再填入缓存命中和输出 token。计算器不直接按像素尺寸估价。实际扣费可在用量记录核对。

局限性

对精确文字、物体数量、模糊图像和位置关系，模型仍可能出错。将模型输出与原始图片核对，关键场景安排人工复核。

概览

生成图片
使用 GPT Image 模型生成或编辑图片。
处理图片输入
使用模型的视觉能力分析图片。

近期的语言模型可以处理图片输入并分析图片，这种能力称为视觉。GPT Image 模型可以结合文本和图片输入来生成新图片，或编辑已有图片。

根据你要分析图片还是生成图片，选择对应的接口：

接口 支持的用途
Responses API 分析图片，或通过图像生成工具生成和编辑图片
Images API 生成图片作为输出，可选择以图片作为输入
Chat Completions API 分析图片并生成文本回复

如需了解模型支持的输入和输出模态，请参阅模型页面。

生成或编辑图片

使用 Images API 时，选择 gpt-image-2.5-sunburst 即可根据文本生成图片或编辑已有图片。使用 Responses API 时，请选择支持图像生成工具的主力模型；GPT Image 模型的选择由该工具自动处理。

    tools=[{"type": "image_generation"}],

import (
	"context"

	"github.com/openai/openai-go/v3"

func main() {
	client := openai.NewClient()

	response, err := client.Responses.New(context.Background(), responses.ResponseNewParams{
		Model: "gpt-6-astra",
		Input: responses.ResponseNewParamsInputUnion{
			OfString: openai.String("生成一张灰色虎斑猫抱着一只戴橙色围巾的水獭的图片。"),
		},
		Tools: []responses.ToolUnionParam{{
			OfImageGeneration: &responses.ToolImageGenerationParam{},
		}},
	})
	if err != nil {
		panic(err)
	}

	for _, output := range response.Output {
		if output.Type != "image_generation_call" {
			continue
		}
		image, err := base64.StdEncoding.DecodeString(output.AsImageGenerationCall().Result)
		if err != nil {
			panic(err)
		}
		if err := os.WriteFile("cat_and_otter.png", image, 0o600); err != nil {
			panic(err)
		}
		return
	}

	panic("response did not include an image generation call")
}

利用世界知识生成图片

GPT Image 模型无需参考图也能利用世界知识。例如，一个描述半宝石陈列柜的提示词，可以生成包含紫水晶、粉水晶、翡翠等可辨认宝石的场景。

分析图片

使用具备视觉能力的模型可以描述图片、读取图中可见的文字，并回答关于物体、形状、颜色或纹理的问题。使用模型的回答时，请考虑模型的局限性。

向模型提供图片输入

使用完整的图片 URL 或 Base64 编码的 Data URL 提供待分析的图片。

你可以在一次请求的 content 数组中放入多张图片。但请注意，图片会计为 token，并按此计费。

def encode_image(image_path):
    with open(image_path, "rb") as image_file:

计算成本

视觉模型会把图片输入转换为可计费的输入 token。本节的图片输入成本计算器以及 patch 和 tile 规则只适用于视觉模型输入，不适用于 GPT Image 的生成或编辑。GPT Image 的单独定价见 GPT Image 模型输入。

图片 token 同样计入你的每分钟 token 数（TPM）限制。计算器按标准输入价格估算单张图片，不包括提示词的其余部分和模型输出。

图片输入成本计算器

使用图片输入成本计算器，可以按模型、图片尺寸和细节级别估算单张图片的输入 token 和费用。

基于 patch 的图片 token 化

部分模型会把图片切分为 32px × 32px 的 patch。许多模型和细节级别组合都定义了缩放 patch 预算。API 首先把图片缩放到所选细节级别的像素尺寸上限之内，保持宽高比，取整到整数像素，且不放大较小的图片。然后按以下步骤计算 token 成本：

A. 在应用像素尺寸上限之后，计算覆盖整张图片所需的 32px × 32px patch 数量。patch 可以超出图片边界。

patch_count = ceil(width/32)×ceil(height/32)

B. 当所选模型和细节级别规定了缩放 patch 预算时，如果图片超出预算，就等比例缩小。否则跳过这一步。取整到整数像素并计算 patch 覆盖后，需要再调整缩放比例，使结果不超出预算。计算最终尺寸前保持全精度。

shrink_factor = sqrt((32^2 * patch_budget) / (width * height))
adjusted_shrink_factor = shrink_factor * min(
  floor(width * shrink_factor / 32) / (width * shrink_factor / 32),
  floor(height * shrink_factor / 32) / (height * shrink_factor / 32)
)

C. 如果第 B 步缩放了图片，把最终的宽和高向下取整为整数像素。计算覆盖缩放后图片所需的 patch 数。这就是应用模型倍率之前的图片 token 数。适用 patch 预算时，这个数值不会超出预算。

resized_patch_count = ceil(resized_width/32)×ceil(resized_height/32)

如果这个数值超过 30,000 个 patch，API 会拒绝该请求。请在应用 token 倍率之前检查这一上限。

D. 将 patch 数乘以模型的倍率，并向上取整，得到可计费的图片输入 token。对这些 token 只按模型的输入价格计费一次；倍率不作用于提示词的其他 token，也不会再次乘到价格上。

gpt-6-astra 在 detail: high 下的图片 token 计算示例

该组合的最大边长为 65,535 像素，patch 预算为 2,500，倍率为 1.2×。

  • 1024 × 1024 的图片需要 32 × 32 = 1024 个 patch。无需缩放。可计费的图片输入为 ceil(1024 × 1.2) = 1229 个 token。
  • 2048 × 2048 的图片最初需要 64 × 64 = 4096 个 patch。patch 预算会将其缩小到 1600 × 1600 像素，即 50 × 50 = 2500 个 patch。估算值为 ceil(2500 × 1.2) = 3000 个 token。
  • 4096 × 512 的图片保持原始尺寸：128 × 16 = 2048 个 patch，即 ceil(2048 × 1.2) = 2458 个 token。

计费时的浮点取整可能使最终数量与估算值相差 1 个 token。

局限性

视觉模型可能出错。设计应用时请考虑以下局限性：

  • 医学图像：该模型不适合解读 CT 等专业医学图像，不应用于提供医疗建议。
  • 非英语文字：处理含有日文、韩文等非拉丁字母文字的图片时，模型效果可能不理想。
  • 小字：放大图中的文字以提高可读性。可用时，使用 "detail": "original" 也有助于提升效果。
  • 旋转：模型可能误读旋转或倒置的文字和图片。
  • 视觉元素：当颜色或样式（如实线、虚线、点线）有变化时，模型可能难以理解图表或文字。
  • 空间推理：模型在需要精确空间定位的任务上表现欠佳，例如识别国际象棋的棋子位置。
  • 准确性：在某些场景下，模型可能生成不正确的描述或标题。
  • 图片形状：模型对全景图和鱼眼图的处理效果欠佳。
  • 元数据与缩放：模型不处理原始文件名或元数据。分析前图片可能会被缩放，即使使用 original 细节级别也是如此。各模型适用的限制见模型尺寸行为。
  • 计数：模型对图中物体数量可能只给出近似值。
  • 验证码：出于安全原因，系统会拦截验证码图片的提交。
