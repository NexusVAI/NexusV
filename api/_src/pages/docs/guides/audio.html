--- title: 音频与语音 description: 了解 NexusVAI API 的实时语音接入方式，区分会话转写与独立音频任务。 tab: models lead: false ---

通过 NexusVAI API 的 GPT-Live，应用可以在同一个会话里发送麦克风音频、接收模型回复，并获得双方的转写文本。实时语音使用 WebSocket。

选择音频工作流

要做什么如何接入
构建可打断的语音对话从实时 API 入门开始。
给现有文本智能体增加语音交互使用 GPT-Live 客户端委托，由你的应用处理后端任务。
从对话中获取字幕或记录读取语音会话的输入与输出转写事件。这不是独立的文件转写接口。
独立文件转写、语音翻译或文字转语音这些作为独立服务未在 NexusVAI 公共 API 开放。接入前请核对端点列表。

用语音构建

先明确用户何时能打断、什么任务需要交给应用后端、双方转写是否需要保存，再从连接示例建立一次完整会话。做评估时，分别观察回复延迟、噪声下的转写和后端任务成功率。资源用量和费用见计费与限制。

选择连接方式

用 WebSocket 访问 chat.nexusvai.xyz 的实时语音端点。NexusVAI 不提供 WebRTC 或 SIP 接入。握手方式和音频格式见连接与认证。

为现有应用添加音频

保留你的文本和工具工作流，通过实时语音会话的客户端委托衔接；不要把音频直接传给文本接口来替代实时语音连接。参数见会话与后端模式。
