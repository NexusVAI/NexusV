如果要开发新的对话式语音应用，请从 GPT-Live 开始。它可以在说话的同时继续聆听，并在后端智能体推理、调用工具或完成任务时保持对话流畅进行。

先用 WebRTC 快速开始建立第一段对话，然后编写一条简短的 Live 提示词。如果你已经有 Realtime 应用或文本智能体，请参阅迁移到 GPT-Live。

选择其他音频工作流

需要 Realtime API 的会话和工具模型时，请使用它。如果是不需要对话智能体的转写、翻译或语音生成，请从下表选择专用 API。

构建目标 从这里开始 你可以控制的内容
基于 Realtime 会话和工具模型的语音到语音智能体 Realtime API 音频轮次、会话状态、工具和打断。
为现有文本智能体添加语音界面 语音智能体 语音转文字、文本智能体工作流，然后文字转语音。
音频文件的转写文本 文件转写 文件上传、有界请求，以及支持的转写格式。
不含助手语音的实时字幕 实时转写 流式音频和增量转写事件。
连续语音翻译 实时翻译 专用的翻译会话，而不是语音智能体的轮次循环。
旁白或生成语音 文字转语音 文本、声音和输出格式。
在现有聊天应用中输入或输出音频 Chat Completions 中的音频 有界的多模态聊天请求。

用语音构建

使用语音智能体比较不同架构。先阅读 GPT-Live 或 Realtime 的提示词指南，再参阅通用指南：自定义语音、评估和成本优化。每篇指南都会区分特定模型或 API 的行为。

选择连接方式

浏览器音频请从 WebRTC 开始。服务端音频管线使用 WebSockets。电话呼叫请参阅电话与 SIP。服务端控制连接可以让可信的后端观察并控制媒体会话。

请在每个连接页面上选择你使用的 API。两者共用同一种传输方式，并不代表 GPT-Live 与 Realtime 的握手、凭证或事件格式可以互换。请阅读对应的连接指南，了解前提条件和设置步骤。

为现有应用添加音频

Chat Completions 的示例现在位于 Chat Completions 中的音频。如需浏览器语音智能体的入门示例，请使用 GPT-Live WebRTC 快速开始。
