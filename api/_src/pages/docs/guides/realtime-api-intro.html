NexusVAI API 通过 GPT-Live 提供全双工语音。应用可以同时发送输入音频、接收回复音频和读取双向转写；后端负责推理和工具执行。

构建语音到语音的智能体

  1. 按连接与认证，使用 API 密钥建立 WebSocket 连接。
  2. 发出 session.start，设置音频格式和委托模式。
  3. 收到 session.started 后，用 session.input_audio.append 持续发送音频。
  4. 处理 session.output_audio.delta 和转写事件，结束时发送 session.close。

从可运行的 Node.js、Python 和浏览器示例开始。不要在公开网页代码里硬编码长期 API 密钥。

应用侧识别与权限

在应用侧维护用户、会话和权限的对应关系。让信任的服务端处理需要凭证的操作，在执行委托任务前核对权限；日志中不要保存 API 密钥或无必要的个人信息。

从其他实时接口接入

不能只替换 Base URL。NexusVAI 使用 /v1/live/sessions 和自身的会话生命周期，不提供 WebRTC、/v1/realtime/calls 或创建临时客户端密钥的 REST 接口。已有实时客户端应按实时语音参考调整握手、音频与事件映射。

后续步骤

建立 WebSocket 连接并发送第一段音频。 配置语音、会话和工具委托。 核对语音时长、后端用量与会话限制。

其他音频工作流

会话可返回实时转写，但不能替代独立的文件转写、翻译或文字转语音接口。见音频与语音。
