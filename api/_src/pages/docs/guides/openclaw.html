--- title: OpenClaw description: 在 openclaw.json 的 models.providers 中添加 NexusVAI，用 Anthropic Messages 或 Responses 协议调用模型。 tab: coding ---

OpenClaw 通过 models.providers 添加自定义 provider。你可以接入一个 Anthropic 兼容的 provider，也可以再加一个 OpenAI Responses 兼容的 provider，两者共用同一个 API 密钥。

前提条件

  • 已安装 OpenClaw。
  • 一个 NexusVAI API 密钥，可以在控制台创建。
  • 要使用的模型 ID，取自 GET /v1/models。

添加 Anthropic 兼容的 provider

编辑 ~/.openclaw/openclaw.json 或项目根目录的 openclaw.json。Anthropic 兼容的 provider 的 baseUrl 不带 /v1：

{
  "env": { "CANCRI_API_KEY": "cancri_sk_..." },
  "agents": {
    "defaults": {
      "model": { "primary": "cancri/claude-opus-5.5" }
    }
  },
  "models": {
    "mode": "merge",
    "providers": {
      "cancri": {
        "baseUrl": "https://cn.nexusvai.xyz",
        "apiKey": "${CANCRI_API_KEY}",
        "api": "anthropic-messages",
        "models": [
          { "id": "claude-opus-5.5", "name": "Claude Opus 5.5" },
          { "id": "claude-sonnet-5.5", "name": "Claude Sonnet 5.5" }
        ]
      }
    }
  }
}
字段说明
env.CANCRI_API_KEY保存 API 密钥，供下面的 ${CANCRI_API_KEY} 引用。
models.mode"merge"：与已有的 provider 配置合并。
providers.cancri.baseUrlhttps://cn.nexusvai.xyz，不带 /v1。
providers.cancri.api"anthropic-messages"，使用 Anthropic Messages 协议。
providers.cancri.models[].idNexusVAI 模型 ID，不带 provider 前缀。
agents.defaults.model.primary默认模型，要带 provider id 前缀，例如 cancri/claude-opus-5.5。

添加 OpenAI Responses 兼容的 provider

想通过 OpenAI 兼容协议调用 gpt-6-astra 等模型时，在同一个文件里再加一个 provider。这一个的 baseUrl 要带 /v1：

{
  "models": {
    "mode": "merge",
    "providers": {
      "cancri-oai": {
        "baseUrl": "https://cn.nexusvai.xyz/v1",
        "apiKey": "${CANCRI_API_KEY}",
        "api": "openai-responses",
        "models": [
          { "id": "gpt-6-astra", "name": "GPT-6 Astra" },
          { "id": "gpt-5.5", "name": "GPT-5.5" }
        ]
      }
    }
  }
}

引用这里的模型时使用 cancri-oai/ 前缀，例如 cancri-oai/gpt-6-astra。

验证配置

启动 OpenClaw，用默认模型发送一条简短的消息。然后查询这个 Key 最近的调用：

curl "https://cn.nexusvai.xyz/v1/balance?limit=5" \
  -H "Authorization: Bearer cancri_sk_..."

recent_usage.data 里应该出现刚才的请求，model 不带 provider 前缀。字段说明见验证请求是否到达 NexusVAI。

排查问题

现象可能的原因解决方法
404，消息为 Not found: /v1/v1/messagesAnthropic 兼容 provider 的 baseUrl 多了 /v1。改成 https://cn.nexusvai.xyz。
421 relay_path_not_supportedResponses provider 的 baseUrl 少了 /v1。改成 https://cn.nexusvai.xyz/v1。
模型不存在models[].id 带了 provider 前缀，或不在 GET /v1/models 中。id 只写模型 ID；只在 primary 等引用处加前缀。
401${CANCRI_API_KEY} 没有取到值，或 Key 已撤销。检查 env 中的变量名与引用是否一致。
