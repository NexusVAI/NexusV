创建响应

POST
/v1/responses

根据输入生成一个模型响应。请求与响应遵循 OpenAI Responses 协议，Codex CLI 等默认使用该协议的客户端可以直接接入；官方 openai SDK 通过 client.responses 调用。用法见 Responses 指南。

网关会把请求转换成 Chat Completions 发给模型，再把结果转换回 Responses 格式，所以只转发下面列出的字段。可用模型与 Chat Completions 相同。

不保存对话状态。响应不会被存储，也没有 GET / DELETE /v1/responses/{id}；previous_response_id、store、background 会被忽略。每次请求都要在 input 中带上完整的对话历史。
请求体
model: string必填

要使用的模型 ID，取值见 GET /v1/models。不存在或已停用时返回 404 model_not_found。

input: string or array必填

模型的输入。字符串等同于一条用户消息；数组按顺序列出对话历史与工具调用记录。
数组中的每一项是以下类型之一：
message: object

一条消息：{"type": "message", "role": "user", "content": …}，type 可以省略。
role: string必填

user、assistant 或 system。

content: string or array必填

字符串，或以下内容块组成的数组：

  • input_text：{"type": "input_text", "text": "…"}。
  • output_text：助手历史消息中的文本。
  • input_image：image_url 为图片 URL 或 data: URL，需要模型支持视觉输入。
  • input_file：用 file_data（data: URL）或 file_url（仅 HTTPS，文本类内容，最大 4 MB）提供文件，网关把内容转成文本后放进上下文，最多保留 1,000,000 个字符；图片类 file_data 按图片处理。不支持 file_id。
function_call: object

模型此前发起的函数调用：{"type": "function_call", "call_id": "…", "name": "…", "arguments": "…"}，按上一轮响应原样回传。

function_call_output: object

函数的执行结果：{"type": "function_call_output", "call_id": "…", "output": "…"}。

其他调用记录: object

custom_tool_call、local_shell_call、shell_call、computer_call、apply_patch_call、web_search_call、mcp_call 及对应的 *_output 会被转换成工具调用与结果。reasoning 等其他类型被忽略。

instructions: string可选

系统指令，作为第一条 system 消息放在 input 之前。

stream: boolean可选默认 false

设为 true 时以 Server-Sent Events 返回 Responses 事件，见流式事件。

max_output_tokens: integer可选

本次最多生成的 token 数，必须是非负数；也接受 max_tokens。都没有设置时按模型目录的输出上限补上。达到上限时 status 为 incomplete。

temperature: number可选

采样温度，必须是非负数。

top_p: number可选

核采样阈值，必须是非负数。

tools: array of object可选

模型可以调用的工具。网关不执行任何工具：所有工具都以函数的形式交给模型，模型的调用以对应类型的输出项返回，由你的客户端执行。
type: string必填

通常为 "function"。custom、shell、local_shell、apply_patch、computer_use_preview 等 Codex 与 Cursor 使用的类型也会被接受并转换成函数；它们的调用分别以 custom_tool_call、shell_call、local_shell_call、computer_call 等输出项返回。web_search、file_search、code_interpreter 不会在服务端执行。

name: string必填

函数名。

description: string可选

函数用途。

parameters: object可选

描述参数的 JSON Schema。

strict: boolean可选

原样转发，是否生效以模型为准。

tool_choice: string or object可选

"auto"、"none"、"required"，或 {"type": "function", "name": "…"} 指定某个函数。

parallel_tool_calls: boolean可选

是否允许一次返回多个函数调用。

text: object可选

文本输出的格式。
format: object可选

{"type": "json_schema", "name": "…", "schema": {…}, "strict": true} 或 {"type": "json_object"}，转换成 Chat Completions 的 response_format；模型不支持结构化输出时会返回错误。默认为纯文本。

verbosity: string可选

会被忽略，不转发给模型。

reasoning: object可选

推理设置。
effort: string可选

推理强度。GPT 系列模型只接受 none、minimal、low、medium、high、xhigh、max，其他值返回 400 invalid_request_parameter。网关只把它转发给已验证支持推理强度的模型（minimal 按 low 转发，none 不转发），其他模型忽略这个字段。

service_tier: string可选

只接受 "auto" 或 "default"（也可以省略）；其他值返回 400 invalid_request_parameter。

其他字段会被忽略，包括 previous_response_id、store、background、include、metadata、truncation、max_tool_calls、conversation、prompt、user 与 reasoning.summary。

返回
id: string

格式为 resp_ 加 24 位十六进制字符。每次请求重新生成，不能用来查询或续接响应。

object: "response"
created_at: integer

创建时间，Unix 时间戳（秒）。

model: string

公开模型 ID。

status: "completed" or "incomplete"

输出达到 max_output_tokens 时为 incomplete。

output: array of object

模型生成的输出项，按生成顺序排列。
每一项是以下类型之一：
message: object

id（msg_ 开头）、type: "message"、status、role: "assistant" 与 content。content 中是 {"type": "output_text", "text": "…", "annotations": []}，模型拒绝回答时是 {"type": "refusal", "refusal": "…"}。

reasoning: object

模型返回思考内容时出现：id（rs_ 开头）、type: "reasoning"，思考文本放在 summary 的 summary_text 中。

function_call: object

函数调用：id（fc_ 开头）、call_id（call_cx 开头）、status、name 与 JSON 字符串形式的 arguments。

其他调用: object

请求中声明了 custom、shell、local_shell、computer_use_preview、web_search 或 mcp 类工具时，对应的调用以 custom_tool_call、shell_call、local_shell_call、computer_call、web_search_call、mcp_call 返回。参数无法解析为对象时，该项 status 为 incomplete，原文放在 _cancri_unparsed_arguments 中，不要执行。

usage: object

input_tokens、output_tokens 与 total_tokens。不包含缓存与思考 token 的明细。

流式事件

每个事件由 event: 行与 data: 行组成，data 中总是带 type（与 event 相同）和递增的 sequence_number。网关不发送 response.in_progress。

response.created

流的第一个事件。response 中 status 为 in_progress，output 为空。

response.output_item.added / .done

一个输出项开始或完成，带 output_index 与 item。

response.content_part.added / .done

消息中的一个内容块开始或完成，带 item_id、output_index、content_index 与 part。

response.output_text.delta / .done

文本增量（delta）与完整文本（text）。拒绝回答时对应 response.refusal.delta / .done。

response.reasoning_summary_text.delta / .done

思考内容的增量与全文，前后有 response.reasoning_summary_part.added / .done。

response.function_call_arguments.delta / .done

函数调用参数的增量与完整参数。custom 与 apply_patch 类工具对应 response.custom_tool_call_input.delta / .done。

response.completed

正常结束，带完整的 response 与 usage。输出达到上限时其中的 status 为 incomplete。

response.incomplete

模型的输出在中途断开或被截断。response.incomplete_details.reason 为 upstream_interrupted、upstream_truncated 或 upstream_empty_response，已输出的项状态为 incomplete。

response.failed

模型报告了错误或没有产生任何内容。response.error 给出 code 与 message，建议换用其他模型或稍后重试。

常见错误
model_not_found: 404

模型不存在、已下架或已停用。

invalid_request_parameter: 400

reasoning.effort 或 service_tier 的取值不被接受，或数值参数为负数。

payload_too_large: 413

请求体超过 10 MB。Codex 等客户端会在 input 中带上整段历史，长会话请先压缩上下文。

insufficient_balance: 402

余额不足以支付本次请求的预估费用，不要自动重试。

rate_limit_exceeded: 429

超出 RPM 或 TPM，按 Retry-After 等待后重试。

upstream_error: 4xx / 5xx

模型暂时不可用、超时或返回了无效响应。稍后重试或换用其他模型。

    max_output_tokens=256,

print(response.output_text)

import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://cn.nexusvai.xyz/v1",
  apiKey: process.env.CANCRI_API_KEY,
});

const tools = [{
  type: "function",
  name: "get_weather",
  description: "查询城市的实时天气",
  parameters: {
    type: "object",
    properties: { city: { type: "string" } },
    required: ["city"],
  },
}];

const response = await client.responses.create({ model: "gpt-6-astra", input: "上海现在天气怎么样？", tools });
for (const item of response.output) {
  if (item.type === "function_call") console.log(item.name, item.arguments);
}
