--- title: API 参考 description: 查阅 NexusVAI API 的端点、请求与响应格式、流式事件，以及认证、错误和速率限制等通用约定。 tab: reference ---

NexusVAI API 在同一个 Base URL 下提供三种文本生成协议：OpenAI Chat Completions、OpenAI Responses 与 Anthropic Messages，另有模型列表、余额查询和实时语音端点。所有端点使用同一把 API 密钥，按同一套规则计费和限速。

开始之前

  1. 选择协议：
    • Chat Completions：通用对话，绝大多数 SDK 与客户端都支持。
    • Responses：Codex CLI 等默认使用 Responses 协议的客户端。
    • Messages：Claude Code、Anthropic SDK 等 Anthropic 协议客户端。
    • 实时语音会话：通过 WebSocket 与 gpt-live-1 进行全双工语音对话。
  2. 在控制台创建 API 密钥（以 cancri_sk_ 开头）。
  3. 安装 OpenAI 或 Anthropic 官方 SDK，把 Base URL 指向 NexusVAI；也可以直接发送 HTTP 请求。步骤见快速开始。
  4. 用 GET /v1/models 选择模型 ID，用 GET /v1/balance 确认密钥有效。
  5. 上线前阅读本页的错误与速率限制响应头，并参考速率限制指南。

端点一览

方法路径用途
POST/v1/chat/completions创建对话补全（OpenAI Chat Completions）
POST/v1/responses创建响应（OpenAI Responses）
POST/v1/messages创建消息（Anthropic Messages）
POST/v1/messages/count_tokens估算 Messages 请求的输入 token 数
GET/v1/models列出可用模型
GET/v1/balance查询账户余额与当前密钥的最近用量
GET（WebSocket）/v1/live/sessions建立 gpt-live-1 实时语音会话

/v1/images/generations 与 /v1/videos/generations 只对网页版开放，通过 API 调用返回 403 endpoint_disabled。本页没有列出的路径（例如 /v1/embeddings、/v1/models/{id}）不存在，返回 404。

Base URL

用途Base URL
OpenAI 协议的 SDK 与客户端https://cn.nexusvai.xyz/v1
Anthropic SDK、Claude Codehttps://cn.nexusvai.xyz（不带 /v1，SDK 会自动拼接 /v1/messages）
实时语音（WebSocket）wss://chat.nexusvai.xyz/functions/v1/api-gateway/v1/live/sessions

也可以使用备用地址 https://chat.nexusvai.xyz/functions/v1/api-gateway（OpenAI 协议在末尾加 /v1），两个地址的密钥、模型 ID、请求格式与计费完全相同。cn.nexusvai.xyz 不支持 WebSocket，实时语音只能连接上表中的 chat.nexusvai.xyz 地址。

认证

NexusVAI API 使用 API 密钥认证。在请求头中用下面任一方式携带密钥：

Authorization: Bearer cancri_sk_...
x-api-key: cancri_sk_...

OpenAI SDK 发送 Authorization，Anthropic SDK 发送 x-api-key，两种写法在所有端点上等价；同时出现时以 Authorization 为准。密钥由前缀 cancri_sk_ 加 48 个 base64url 字符组成，共 58 个字符。

curl https://cn.nexusvai.xyz/v1/balance \
  -H "Authorization: Bearer $CANCRI_API_KEY"
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://cn.nexusvai.xyz/v1",
    api_key=os.environ["CANCRI_API_KEY"],  # 以 Authorization: Bearer 发送
)
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  baseURL: "https://cn.nexusvai.xyz",
  apiKey: process.env.CANCRI_API_KEY, // 以 x-api-key 发送
});
  • GET /v1/models 不校验密钥；其他端点缺少密钥或密钥无效时返回 401 invalid_api_key。
  • 同一网络在短时间内反复使用不存在的密钥，会暂时收到 429 auth_rate_limited，请按 Retry-After 等待。
  • 团队密钥的格式与个人密钥相同，费用从团队余额扣除，速率限制按团队计算，见团队。
  • API 密钥只用于 /v1/* 接口；网页登录会话不能代替密钥。

密钥是机密。不要把它写进浏览器代码、移动应用或公开仓库。API 只允许 NexusVAI 自己的网站跨域调用，第三方网页无法在浏览器里直接请求；请从你的服务端发起请求，把密钥放在环境变量或密钥管理服务中。

请求与响应约定

三个文本生成端点共用下面的规则。各端点还有自己的字段说明，见对应的参考页。

项目规则
请求体JSON 对象，Content-Type: application/json。不是合法的 JSON 对象时返回 400。
大小上限10 MB（10,485,760 字节），超出返回 413 payload_too_large。
model填 GET /v1/models 返回的 ID。响应中的 model 始终是这个公开 ID。
数值参数max_tokens、max_output_tokens、temperature、top_p 必须是非负的有限数，否则返回 400 invalid_request_parameter。
service_tier只接受省略、null、"auto"、"default"，其他值返回 400 invalid_request_parameter。接受的值也不会转发给模型。
推理强度GPT 系列模型（ID 含 gpt-）的 reasoning_effort 与 reasoning.effort 只接受 none、low、medium、high、xhigh、max（reasoning.effort 另接受 minimal）。
输出上限没有设置 max_tokens、max_completion_tokens 或 max_output_tokens 时，网关按模型目录补上 max_tokens，取值与 GET /v1/models 中的 max_output_tokens 相同。
字段转发Chat Completions 原样转发参考页未列出的字段。Responses 与 Messages 会先转换成 Chat Completions，只转发参考页列出的字段，其余字段被忽略。
ID响应 ID 由 NexusVAI 生成（chatcmpl-、resp_、msg_ 前缀）。工具调用 ID 改写为 call_cx 或 toolu_cx 开头，同一个调用在流式与非流式响应中、以及你在下一轮回传时保持一致。
usage只返回 token 数量（Chat Completions 另含 completion_tokens_details.reasoning_tokens），不返回缓存命中明细。缓存折扣已计入扣费，可在 GET /v1/balance 的 cost 中核对。
超时网关等待模型开始响应最多 180 秒，超时返回 504。流式响应开始输出后不再受这个限制。

流式输出

在请求中设置 "stream": true，三个文本生成端点都会以 Server-Sent Events（text/event-stream）返回增量结果：

端点事件格式结束标志用量
Chat Completions每行 data: {chat.completion.chunk}data: [DONE]最后一个数据块（choices 为空）
Responsesevent: response.*，数据中带 type 与 sequence_numberresponse.completedresponse.completed 的 usage
Messagesevent: message_start、content_block_*、message_deltamessage_stopmessage_delta 的 usage
 
curl https://cn.nexusvai.xyz/v1/chat/completions \
  -N \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $CANCRI_API_KEY" \
  -d '{
    "model": "deepseek-v4-flash",
    "messages": [{"role": "user", "content": "写一句问候语"}],
    "stream": true
  }'
import os
from openai import OpenAI

client = OpenAI(base_url="https://cn.nexusvai.xyz/v1", api_key=os.environ["CANCRI_API_KEY"])

stream = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[{"role": "user", "content": "写一句问候语"}],
    stream=True,
)
for chunk in stream:
    if chunk.choices:
        print(chunk.choices[0].delta.content or "", end="", flush=True)
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "https://cn.nexusvai.xyz/v1", apiKey: process.env.CANCRI_API_KEY });

const stream = await client.chat.completions.create({
  model: "deepseek-v4-flash",
  messages: [{ role: "user", content: "写一句问候语" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content || "");
}
  • Chat Completions 的流式请求总会被设置 stream_options.include_usage: true，所以最后一个数据块一定带 usage。
  • 模型思考较久时，Chat Completions 流中会出现 : keep-alive 注释行，按 SSE 规范忽略即可。
  • 流开始后才发生的错误不会改变 HTTP 状态码（已经是 200），而是以协议内的事件返回：Chat Completions 为带 error 字段的数据块，Responses 为 response.failed 或 response.incomplete，Messages 为 event: error。具体取值见各端点页。
  • 中途断开连接（例如用户按下停止）不会撤销计费，网关仍按已发送的输入和已生成的输出结算。

速率限制响应头

速率限制按账户计算（团队密钥按团队计算），指标是 RPM（每分钟请求数）与 TPM（每分钟 token 数）。Chat Completions 与 Responses 的响应带以下响应头：

响应头说明
x-ratelimit-limit-requestsRPM 上限
x-ratelimit-remaining-requests剩余的请求数
x-ratelimit-reset-requests请求额度恢复到上限所需的时间，例如 1s、6m0s
x-ratelimit-limit-tokensTPM 上限
x-ratelimit-remaining-tokens剩余的 token 数
x-ratelimit-reset-tokenstoken 额度恢复到上限所需的时间

Messages 返回对应的 anthropic-ratelimit-requests-limit、anthropic-ratelimit-requests-remaining、anthropic-ratelimit-requests-reset 与 anthropic-ratelimit-tokens-*，其中 reset 是 RFC 3339 时间。响应头的值取账户限额与密钥限额中更严的一层。超出限额时返回 429 rate_limit_exceeded，error.limit 为 requests 或 tokens，error.scope 为 account 或 key。各档位的数值见速率限制。

错误

错误使用标准 HTTP 状态码，error.code 给出具体原因。请按 error.code 处理错误，不要依赖 message 的文字。

{
  "error": {
    "message": "Invalid API key. Provide a valid key as Bearer token (Authorization) or x-api-key header.",
    "type": "authentication_error",
    "code": "invalid_api_key"
  }
}
{
  "type": "error",
  "error": {
    "type": "rate_limit_error",
    "message": "Rate limit reached for requests per minute (RPM): limit 60. Please try again in 2s.",
    "code": "rate_limit_exceeded"
  }
}
  • Chat Completions、Responses、/v1/models、/v1/balance 与实时语音握手使用 OpenAI 格式。
  • Messages 的模型、计费、限流与上游错误使用 Anthropic 格式；认证、请求体校验与密钥限制这些前置检查返回的错误仍是 OpenAI 格式。
  • /v1/messages/count_tokens 使用 Anthropic 格式，且不含 code 字段。
  • 官方 SDK 都能解析这两种格式。自己解析时，先读 error.code，再读 error.type。

重试

  • 响应带 Retry-After 时，按其取值（秒）等待后重试。
  • 响应带 x-should-retry: false 时不要重试：402 insufficient_balance、429 request_too_large、429 free_plan_exhausted、429 key_token_quota_exhausted、429 key_request_quota_exhausted。官方 OpenAI 与 Anthropic SDK 会读取这个响应头，自动停止重试。
  • 其他 429 与 5xx 没有 Retry-After 时，使用带随机抖动的指数退避。
  • 400、401、403、404 需要先修正请求或配置，原样重试不会成功。

版本与兼容性

  • 路径固定为 /v1，没有单独的 API 版本号或版本请求头。anthropic-version 可以照常发送，网关不校验它的取值。
  • 请求与响应遵循 OpenAI 与 Anthropic 的公开协议，官方 SDK 可以直接使用。各端点页列出了网关读取、改写或忽略的字段。
  • 网关不保存对话状态：Responses 的 previous_response_id、store、background 会被忽略，每次请求都要带上完整上下文。网关也不执行任何工具，网页搜索、文件检索、代码解释器等托管工具不会在服务端运行。
  • 模型会上下架，以 GET /v1/models 为准；部分已退役的模型 ID 会被自动映射到替代模型。目录变化可能要几分钟后才反映到 GET /v1/models。
