创建对话补全

POST
/v1/chat/completions

为一组对话消息生成一条模型回复。请求与响应遵循 OpenAI Chat Completions 协议，官方 openai SDK 把 Base URL 指向 https://cn.nexusvai.xyz/v1 即可调用。用法见 Chat Completions 指南。

网关会校验并解析 model，在你没有设置输出上限时补上模型的默认上限，其余字段原样转发给模型。响应返回前会整理成标准格式：只保留 OpenAI 定义的字段，id 与工具调用 ID 由 NexusVAI 生成。

返回一个 chat.completion 对象；设置 stream: true 时返回 chat.completion.chunk 事件流。

请求头
Authorization: string必填

Bearer cancri_sk_…。也可以改用 x-api-key: cancri_sk_…，见认证。

请求体
model: string必填

要使用的模型 ID，取值见 GET /v1/models 或模型目录。模型不存在或已停用时返回 404 model_not_found；只在桌面端开放的模型返回 403 model_ide_only。

messages: array of object必填

到目前为止的对话消息，按时间顺序排列。请求体没有 messages 而带有 Responses 风格的 input 时，网关会先把 input 转换成 messages，响应仍是 Chat Completions 格式。
role: string必填

消息作者：system、user、assistant 或 tool。

content: string or array

消息内容。可以是字符串，也可以是内容块数组：{"type": "text", "text": "…"} 或 {"type": "image_url", "image_url": {"url": "…"}}（图片 URL 或 data: URL）。图片只在支持视觉输入的模型上可用，只接受文本的模型会返回 400 image_input_unsupported。助手消息只包含工具调用时可以为 null。

tool_calls: array of object可选

助手消息中模型此前发起的工具调用，按上一轮响应原样回传。

tool_call_id: string可选

role 为 tool 时必填：这条结果对应的工具调用 id。

name: string可选

参与者名称，按 OpenAI 规范原样转发。

stream: boolean可选默认 false

设为 true 时以 Server-Sent Events 返回增量结果，见流式输出。

stream_options: object可选

流式选项。流式请求的 include_usage 总会被设为 true，所以最后一个数据块一定携带 usage。

max_tokens: integer可选

本次最多生成的 token 数，必须是非负数。max_tokens 与 max_completion_tokens 都没有设置时，网关按模型目录补上 max_tokens，取值与 GET /v1/models 返回的 max_output_tokens 相同。这个值也用于预占本次请求的 TPM。

max_completion_tokens: integer可选

OpenAI 的新字段名，原样转发。设置后网关不再补 max_tokens。

temperature: number可选

采样温度，必须是非负数，越高输出越随机。取值范围与默认值以模型为准（OpenAI 规范为 0–2）。

top_p: number可选

核采样阈值，必须是非负数。

tools: array of object可选

模型可以调用的函数工具，是否支持以模型为准。Responses 风格的工具（扁平的 {"type": "function", "name": …}，或 shell、apply_patch 等类型）会先被转换成下面的标准形式；网关不执行任何工具，调用结果需要你在下一轮请求中回传。
type: "function"必填
function: object必填

函数定义。
name: string必填

函数名。

description: string可选

函数用途，模型据此决定何时调用。

parameters: object可选

描述参数的 JSON Schema。

strict: boolean可选

要求参数严格符合 Schema，原样转发，是否生效以模型为准。

tool_choice: string or object可选

"none"、"auto"、"required"，或 {"type": "function", "function": {"name": "…"}} 指定某个函数。

parallel_tool_calls: boolean可选

是否允许一次返回多个工具调用，原样转发。

response_format: object可选

结构化输出：{"type": "json_object"} 或 {"type": "json_schema", "json_schema": {…}}。原样转发，是否支持以模型为准。

stop: string or array可选

停止序列，原样转发。

reasoning_effort: string可选

推理强度。GPT 系列模型（ID 含 gpt-）只接受 none、low、medium、high、xhigh、max，其他值返回 400 invalid_request_parameter；其他模型原样转发。

service_tier: string可选

只接受 "auto" 或 "default"（也可以省略），且不会转发给模型；其他值返回 400 invalid_request_parameter。

其他 Chat Completions 字段（如 n、seed、frequency_penalty、presence_penalty、logprobs、user）原样转发，是否生效取决于所选模型。

返回
id: string

本次补全的 ID，格式为 chatcmpl- 加 24 位十六进制字符，由 NexusVAI 生成。

object: "chat.completion"
created: integer

创建时间，Unix 时间戳（秒）。

model: string

生成回复的模型 ID，始终是 GET /v1/models 中的公开 ID。

choices: array of object

生成的回复。设置了 n 且模型支持时可能有多条。
index: integer
message: object

模型生成的消息。
role: "assistant"
content: string or null

回复文本。只有工具调用时为 null。

reasoning_content: string

部分模型返回的思考内容，只在模型提供时出现。

tool_calls: array of object

模型发起的工具调用。每项包含 id（call_cx 开头，由 NexusVAI 改写）、type（"function"）与 function（name，以及 JSON 字符串形式的 arguments）。

refusal: string or null

模型拒绝回答时的说明，只在模型提供时出现。

finish_reason: string

停止原因，例如 stop（自然结束或命中停止序列）、length（达到输出上限）、tool_calls（发起了工具调用）。取值来自模型。

logprobs: object or null

请求了 logprobs 且模型支持时返回。

usage: object

本次请求的 token 用量。不返回缓存命中明细（prompt_tokens_details）；缓存折扣已计入扣费，可在 GET /v1/balance 的 cost 中核对。
prompt_tokens: integer

输入 token 数。

completion_tokens: integer

输出 token 数。

total_tokens: integer

输入与输出之和。

completion_tokens_details: object

只包含 reasoning_tokens（思考消耗的 token 数），仅在模型提供时返回。

模型返回的其他字段（如 system_fingerprint、service_tier）会被移除。

流式输出

每个事件是一行 data: <JSON>，流以 data: [DONE] 结束。模型思考较久时流中会出现 : keep-alive 注释行，按 SSE 规范忽略即可。数据块的字段如下。

object: "chat.completion.chunk"

同一次请求的所有数据块使用同一个 id，model 同样是公开模型 ID。

choices: array of object

增量内容。
delta: object

本块新增的 role、content、reasoning_content 或 tool_calls。工具调用的 arguments 分多块给出，按 index 拼接。

finish_reason: string or null

在最后一个内容块中给出，其余为 null。

usage: object

只出现在 [DONE] 之前的最后一个数据块，此时 choices 为空数组。字段与非流式响应的 usage 相同。

error: object

流开始后才发生的错误。HTTP 状态码已是 200，所以错误以带 error 字段的数据块返回，紧跟一个 data: [DONE]。
code: string
  • model_temporary_failure：模型暂时繁忙，没有产生内容，本次不计费。可在 retry_after_seconds（30）秒后重试，或换用其他模型。
  • stream_incomplete_billed：回复不完整，已按实际产生的 token 计费，billed 为 true。重试会产生一次新的计费请求。
  • upstream_stream_interrupted：连接在回复中途断开，回答不完整。
message: string

可展示给用户的说明（中文）。

type: "api_error"

流式请求中途断开连接（例如用户按下停止）不会撤销计费：网关仍按已发送的输入和已生成的输出结算。

常见错误
model_not_found: 404

模型不存在、已下架或已停用。用 GET /v1/models 核对 ID，大小写与连字符必须完全一致。

invalid_request_parameter: 400

service_tier 或 reasoning_effort 的取值不被接受（error.param 指出字段），或 max_tokens、temperature、top_p 为负数。

model_not_in_whitelist: 403

密钥设置了模型白名单（或绑定了模型分组，此时为 model_not_in_group），所选模型不在其中。

insufficient_balance: 402

余额不足以支付本次请求的预估费用。响应带 x-should-retry: false，充值后再试。

rate_limit_exceeded: 429

超出账户或密钥的 RPM / TPM。按 Retry-After 等待后重试。

upstream_error: 4xx / 5xx

模型暂时不可用、超时或返回了无效响应，与你的密钥和余额无关。稍后重试或换用其他模型。

import os
from openai import OpenAI

client = OpenAI(
    base_url="https://cn.nexusvai.xyz/v1",
    api_key=os.environ["CANCRI_API_KEY"],
)

completion = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[
        {"role": "system", "content": "你是一个简洁的助手。"},
        {"role": "user", "content": "用一句话解释什么是 RLS。"},
    ],
)
print(completion.choices[0].message.content)
