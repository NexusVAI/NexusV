编程工具

在 Codex、Claude Code、Cursor 等编程工具和聊天客户端中使用 NexusVAI 的模型。

任何允许自定义 Base URL、API 密钥和模型 ID 的工具，都可以接入 NexusVAI。NexusVAI 同时兼容 OpenAI 的 Chat Completions、Responses 和 Anthropic 的 Messages 协议，所以命令行智能体、编辑器扩展和桌面客户端通常只需要改三项配置，不用改代码。

支持的工具

下表列出已有接入指南的工具、它们使用的协议，以及 Base URL 应该怎么填。

工具类型协议Base URL
Codex CLI命令行智能体Responses带 /v1
Claude Code命令行智能体Anthropic Messages不带 /v1
OpenCode命令行智能体Chat Completions（默认），也可用 Responses带 /v1
OpenClaw命令行智能体Anthropic Messages 或 ResponsesMessages 不带 /v1；Responses 带 /v1
Aider命令行智能体OpenAI 兼容（经 LiteLLM）带 /v1
Cursor编辑器OpenAI 兼容带 /v1
ClineVS Code 扩展OpenAI 兼容带 /v1
ContinueVS Code / JetBrains 扩展OpenAI 兼容带 /v1
Cherry Studio桌面客户端OpenAI 兼容带 /v1
Chatbox桌面客户端OpenAI 兼容带 /v1
LobeChat聊天应用OpenAI 兼容带 /v1
SillyTavern聊天前端Chat Completions带 /v1
CC Switch多工具配置管理取决于目标工具按目标工具填写

部分编辑器（例如 Cursor）的 Agent、行内补全等功能可能仍然使用厂商自己的服务，自定义 Base URL 通常只对对话生效。需要完整的编程智能体时，优先选择 Claude Code、Codex CLI、Cline 或 Continue。

填写 Base URL

客户端会在 Base URL 后面自动拼接端点路径，所以要按协议填写：

协议Base URL客户端实际请求
OpenAI 兼容（Chat Completions、Responses）https://cn.nexusvai.xyz/v1/v1/chat/completions、/v1/responses、/v1/models
Anthropic Messageshttps://cn.nexusvai.xyz/v1/messages、/v1/messages/count_tokens、/v1/models

Anthropic 兼容的工具不要在 Base URL 末尾加 /v1。Claude Code、Anthropic SDK 和 OpenClaw 会自己拼接 /v1/messages，填成 https://cn.nexusvai.xyz/v1 会请求 /v1/v1/messages，返回 404。

如果你的网络访问 cn.nexusvai.xyz 不稳定，可以改用 https://chat.nexusvai.xyz/functions/v1/api-gateway：OpenAI 兼容工具在末尾加 /v1，Anthropic 兼容工具不加。两个地址的 Key、模型 ID、请求格式和计费完全相同。

设置 API 密钥

在控制台创建一个以 cancri_sk_ 开头的 API 密钥。命令行工具通常从环境变量读取 Key，建议保存在环境变量里，而不是写进项目文件：

设置环境变量
macOS / Linux
1
2# 当前终端生效；写进 ~/.zshrc 或 ~/.bashrc 可长期生效
export CANCRI_API_KEY="cancri_sk_..."
1
2
3
4# 当前窗口生效
$env:CANCRI_API_KEY = "cancri_sk_..."
# 长期生效（对之后新开的终端有效）
setx CANCRI_API_KEY "cancri_sk_..."

网页登录的会话和 Cookie 不能代替 API 密钥。认证方式的完整说明见认证与 API 密钥。

选择模型

三种协议共用同一份模型列表：Claude Code 也可以调用非 Claude 模型，Codex CLI 也可以调用 Claude 模型，前提是客户端允许你手动填写模型 ID。列出当前可用的模型：

列出模型
1
2curl https://cn.nexusvai.xyz/v1/models \
  -H "Authorization: Bearer $CANCRI_API_KEY"
  • 模型 ID 必须与 GET /v1/models 返回的 id 完全一致，包括大小写和连字符。
  • 不要使用模型厂商的原始版本号（例如 claude-3-5-sonnet-20241022），也不要沿用其他服务的型号或别名（例如 gpt-4o）。
  • 本节指南的示例使用 gpt-6-astra（Codex CLI 推荐的编码模型）和 claude-opus-5.5，你可以换成列表中的任意模型。

各模型的能力和价格见模型与价格。

验证请求是否到达 NexusVAI

配置完成后，先在工具里发一条简短的消息，再查询这个 Key 最近的调用记录。GET /v1/balance 不计费：

查询余额与最近的调用
1
2curl "https://cn.nexusvai.xyz/v1/balance?limit=5" \
  -H "Authorization: Bearer $CANCRI_API_KEY"

返回 200 说明 Base URL 和 Key 都有效。如果 recent_usage.data 里出现了刚才的请求，说明工具确实把请求发到了 NexusVAI：

字段说明
balance账户余额（元）。网页与所有 Key 共用同一个余额。
recent_usage.data[].model请求使用的模型 ID。
recent_usage.data[].prompt_tokens、completion_tokens输入和输出 token 数。
recent_usage.data[].status_code请求的 HTTP 状态码。
recent_usage.data[].cost这次请求的实际扣费（元）。

limit 取 0–100，默认 20。记录只包含当前这个 Key 的调用。
